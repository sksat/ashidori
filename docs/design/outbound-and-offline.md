# 外部への送信の設定とオフラインの地域データ（設計案）

> 状態：**提案**。未実装である。
> 外部のレビュー（1 回目）の指摘を反映した。レビューは、送信の契約、設定の破損と旧版との互換、保存の復旧と容量の管理、詳細画面の一括の適用が決まるまで実装に入らないことを条件とした。
> 容量の計測と通信の経路を確かめる試作は先に進めてよい。製品に組み込む前に、設定の変更、再起動、リダイレクトを含む端末での試験を必須とする。
> 利用者の判断を待つ点を [未決の事項](#9-未決の事項) に挙げる。
> 外部のサービスについて確かめていない事項は「未確認」と書く。
> 現行の仕様は [`privacy.md`](../privacy.md) と [README の「地名と位置情報の送信」](../../README.md#地名と位置情報の送信) にある。

本書は二つの機能を扱う。

1. **送信先ごとの外部送信の設定**：送信先ごとに、送るかどうか、いつ送るか、どの精度まで送るかを利用者が決める。
2. **オフラインの地域データ**：地域を選び、詳細な地図と施設データを事前に端末へ取得する。

二つは互いに関わる。
地域データがあればオンライン地図に頼らずに済み、地域データの取得自体も外部への送信の一つになる。

## 1. 課題と目標

### 課題

- 外部への送信を制御する設定は「オンライン地図と地名検索」のスイッチ一つ（保存値 `blockExternalLocation`）だけである。
- 実際の送信先は複数あり、送る情報も精度も異なる。地図の配信元には表示範囲を、Android の Geocoder には滞在地の座標を、Overpass には検索した位置を送る。
- 利用者には「この送信先にこの精度なら送ってよいが、あの送信先には送らない」という判断がありうる。一つのスイッチではこれを表せない。
- オフライン地図は日本でズーム 10、全世界でズーム 5 までである。通信できない場所（山、海外の旅行先）で詳細な地図を見る手段がない。

### 目標

1. 送信先ごとに、送信の可否、時機（操作時のみ、自動）、精度を選べる。
2. 新規の導入の既定と、既存の利用者の動作を変えない。
3. 設定の結果を ✓ ／ ⊖ の一覧で示し、説明の段落を置かない。
4. 地域を選んで、詳細な地図と施設データを事前に取得できる。取得で何が誰に伝わるかが画面で分かる。
5. 地域データの取得と更新が記録を妨げない（記録の領域を残し、記録の処理と独立に動く）。

### 対象外

- OS の測位サービスが送る情報（fused と network provider、Google 位置情報の精度）。一覧には参照の行だけを置く（[未決 5](#9-未決の事項)）。
- Web ビューア（ブラウザ）の地図。ブラウザの設定はブラウザに保存する別の仕組みである（[`web-viewer.md`](../web-viewer.md)）。
- 同期プロトコルの変更。

### 2.3 一覧から分かること

- Geocoder には、自分の滞在地だけでなく、同期した他の端末の現在地も送りうる（`PeerStatus.scala:321`）。
- Overpass の予備のインスタンスは、1 回の検索の送信先を最大 4 ホスト、3 者に広げる。
- 静止画（フィード、期間のカード、他の端末）は、設定がオンの間、過去の日の範囲を地図の配信元へ自動で送る。表示中の地図より伝わる範囲が広い。
- 地図と静止画の送信先は、選んだ地図（`mapStyle`）で決まる。**例外は地図の種類のサムネイル**であり、送信が許される候補をすべて現在の表示範囲で描く。選んでいない地図の配信元にも表示範囲が伝わる。
- MapLibre の出典の画面は、出典の URL によってはカメラの位置をブラウザに渡す。

## 3. 設定とデータのモデル

### 3.1 送信先と選べる値

設定は送信先（`Dest`）ごとの規則（`Rule`）の集まりとする。
規則は時機（`When`）と精度（`Level`）の組である。

| `Dest` | 画面の名前 | 選べる時機 | 選べる精度 |
| --- | --- | --- | --- |
| `ofm` | オンライン地図（OpenFreeMap） | 送信しない、操作時のみ、自動 | 地域、地区、制限なし |
| `gsi` | オンライン地図（地理院タイル） | 同上 | 同上 |
| `custom` | オンライン地図（カスタム） | 同上 | 同上 |
| `geocoder` | 地名検索（Android） | 送信しない、自動 | 地域、地区、正確 |
| `overpass` | 施設のオンライン検索 | 送信しない、操作時のみ | 地区、正確 |
| `data` | 地図・施設データの取得 | 送信しない、操作時のみ、自動 | 全域のみ、区画 |

時機の意味は次のとおりである。

- **送信しない**：その送信先には、操作があっても送らない。入口（ボタン、地図の種類）を無効にする。
- **操作時のみ**：利用者がその表示やその検索を指示したときだけ送る。地図では今の「オンライン地図で表示（表示範囲を送信）」に当たり、一度許した地図は、その画面でオフライン地図に戻すか設定を変えるまで保つ（画面を離れても、再起動しても続く）。
- **自動**：表示や記録に合わせて送る。地図では静止画とサムネイルも含む。

Geocoder には操作の入口がないので「操作時のみ」を置かない。
Overpass には自動の検索を設けない（今の方針を保つ）。

### 3.2 精度の意味

精度は、**送る座標やタイル番号の粒度**である。
送信先から見た位置の候補の範囲（最低の匿名範囲）は保証しない。

| 精度 | 地図のタイル（T1〜T3） | 地名検索 | 施設の検索 |
| --- | --- | --- | --- |
| 地域（約 10 km） | ズーム 12 までのタイル番号を送る。それより拡大した表示はズーム 12 のタイルを引き伸ばす | 0.1° の格子の中心の座標を送り、答えは市区町村と国だけを使う | 選べない |
| 地区（約 1 km） | ズーム 15 までのタイル番号を送る | 0.01° の格子の中心の座標を送る | 0.01° の区画とその周囲 8 区画を合わせた bbox を送り、端末内で近い順に絞り込む |
| 制限なし、正確 | 配信元の最大ズームまで | 座標のまま | 位置と半径のまま |

粒度は位置を隠す範囲ではない。
送信先は、次の手がかりで粒度より細かく位置を推測しうる。

- **隣り合うタイル**：表示範囲が上限のズームのタイルの境界をまたぐと、隣り合うタイルを要求する。表示の中心が境界の近くにあると分かる。
- **順序と時刻**：MapLibre は中心に近いタイルから要求する傾向がある。要求の順序と時刻、既知の画面の大きさから、表示の中心と範囲を絞れる。
- **緯度による縮み**：格子とタイルの実寸は緯度で変わる。0.01° の経度は北緯 35° で約 0.9 km、北緯 60° で約 0.56 km である。タイルの 1 辺は `40075 km × cos(緯度) / 2^z` であり、北緯 35° でズーム 12 は約 8 km、ズーム 15 は約 1 km である。
- **境界の通過**：格子は固定である（毎回同じ区画の中心を送る）。区画の境界を越えた時刻は伝わり、道路などの補助の情報と合わせると移動の経路を絞れる。
- **Overpass の 9 区画**：周囲 8 区画を含めても、bbox の中央の区画は一意に分かる。伝わる粒度は約 3 km 四方ではなく、中央の 0.01° の区画である。周囲を含めるのは、半径の検索が区画の境界で切れないためである。

ほかに次の点を定める。

- OpenFreeMap のベクタタイルの最大ズームは 14 と理解している（未確認）。その場合、OpenFreeMap の「地区」と「制限なし」は同じ要求になる。
- 地名検索の「地域」は「…付近」の地名を出さない。ずらした点の町名は誤りになりうるためである。
- 区画ごとに決まったタイルの集合を常に要求する方式（表示によらず同じ集合を送る）は、隣り合うタイル、順序、時刻による推測を減らすが、通信量が増える。将来の案として残す。

「データの取得」の精度は次のとおりである。

| 精度 | 意味 |
| --- | --- |
| 全域のみ | 日本と全世界のオフライン地図、日本の施設データのように、利用者の選んだ範囲を含まない archive だけを取得する。地域データは取得しない。日本全体を取得した事実と IP アドレスは伝わる |
| 区画 | 加えて、利用者が選んだ地域の区画（[6.4 節](#64-区画)、約 130 km 四方）を取得する |

### 3.3 型

`core` に置く。

```scala
enum Dest(val key: String):
  case Ofm extends Dest("ofm")
  case Gsi extends Dest("gsi")
  case CustomTiles extends Dest("custom")
  case Geocoder extends Dest("geocoder")
  case Overpass extends Dest("overpass")
  case Data extends Dest("data")

enum When:
  case Never, OnAction, Auto

/** 送信先ごとに意味が異なる。Whole と Cell は Data だけが使う。 */
enum Level:
  case Area, District, Exact, Whole, Cell

/** off: Overpass で使わないインスタンスのホスト。 */
final case class Rule(when: When, level: Level, off: Set[String] = Set.empty)

final case class Policy(rules: Map[Dest, Rule]):
  def rule(d: Dest): Rule
```

`Policy` は、送信先ごとに選べない組（Geocoder の `OnAction` など）を持たない。

### 3.4 保存するキー

既存の `settings` の SharedPreferences に置く。

| キー | 型 | 既定 | 内容 |
| --- | --- | --- | --- |
| `externalPolicy` | String（JSON） | なし（なければ移行する） | 送信先ごとの規則 |
| `externalConsents` | String（JSON） | なし（なければ `mapConsents` から移行する） | 地図の画面ごとの同意。送信先と精度を含む |
| `mapConsents` | String（JSON） | 既存 | 移行の元。移行後は読まず、旧版向けの派生値を書く（[3.6 節](#36-旧版との互換)） |
| `blockExternalLocation` | Boolean | 既存 | 移行の元。移行後は読まず、旧版向けの派生値を書く |
| `externalPaused` | Boolean | false | 一時停止（[4.5 節](#45-一時停止)） |
| `regionsAutoUpdate` | Boolean | 取得の画面で決める | 地域データの自動更新（[6.12 節](#612-管理の一覧と更新)） |
| `regionsMetered` | Boolean | false | 地域データをモバイルデータ通信でも取得するか |

`externalPolicy` は `MapConsents` と同じく、版付きの一つの JSON とする。

```json
{"v":1,"rules":[
  {"dest":"custom","when":"action","level":"exact"},
  {"dest":"data","when":"auto","level":"cell"},
  {"dest":"geocoder","when":"never","level":"exact"},
  {"dest":"gsi","when":"action","level":"exact"},
  {"dest":"ofm","when":"action","level":"exact"},
  {"dest":"overpass","when":"action","level":"exact","off":[]}
]}
```

規則と同意と旧版向けの派生値は、一度の `SharedPreferences.Editor` で書く（今の `persist` と同じ）。

### 3.5 既定値、復旧値、読み込みの順序

**新規の導入の既定**と、**読めない値からの復旧値**を分ける。

| 送信先 | 新規の導入の既定（今の動作） | 復旧値 |
| --- | --- | --- |
| `ofm`、`gsi`、`custom` | 操作時のみ、制限なし | 送信しない |
| `geocoder` | 送信しない | 送信しない |
| `overpass` | 操作時のみ、正確、全インスタンス | 送信しない |
| `data` | 自動、区画 | 操作時のみ、全域のみ（手動の取得だけ） |

復旧値は、値が壊れている場合、未知の版の場合、送信先の項目が欠けている場合に使う。
同意はすべて捨てる。
`data` だけは「送信しない」ではなく「操作時のみ」とする。オフライン地図を手動でなら取得できるようにするためであり、自動の取得と自動更新は止まる。

読み込みは次の順に行う。

1. 重複したキーを拒む解析で JSON を読む。読めなければ破損とする。
2. `v` を見る。1 でなければ未知の版とする。
3. 既知の送信先の規則から未知の項目を除き、未知の送信先の規則を除く。
4. 除いた後の値を `Policy` に復号し、符号化し直したものが、除いた後の値の正準形と一致することを確かめる。送信先の重複、選べない組、型や値の誤りはここで不一致になり、破損とする。
5. 欠けている送信先を復旧値で補う。アプリの更新で送信先を加える場合は、`Settings.migrate()` がその送信先の既定を明示的に書く。読み込みで欠けていれば、それは移行の漏れか破損であり、復旧値を使う。

破損と未知の版の値は、保存し直さない。
新しい版のアプリが書いた値は、利用者がこの版で設定を変えるまで残る。
「データの扱い」の画面は、この状態の間「設定を読み込めません（送信を停止中）」の 1 行を出す。
利用者が変えた時点で、この版の形式で書く。

### 3.6 旧版との互換

旧版のアプリ（`blockExternalLocation` と `mapConsents` だけを読む）に戻した場合の保証は、旧版の Boolean が表せる範囲に限る。

**保証すること**：旧版は、新しい設定が自動の送信を許していない地図の配信元と Geocoder へ、自動では送らない。
`blockExternalLocation` の派生値は、規則がすべて旧設定のオフ（[3.7 節](#37-移行)の右列）と一致するときだけ false、ほかは true とする。

**`mapConsents` の派生値**：精度が「制限なし」で、送信先が「操作時のみ」の同意だけを書く。
精度に制限のある同意は旧版に渡さない。
旧版は精度の制限を知らず、制限なしで送るためである。

**保証できないこと**（旧版の `blockExternalLocation=true` の動作による反例）：

- Overpass を「送信しない」にしても、旧版は「オンラインで検索」を押せば送る。
- `data` を「操作時のみ」「送信しない」にしても、旧版は起動時にオフライン地図と施設データを自動で取得する。
- 地図の送信先を「送信しない」にしても、旧版は「オンライン地図で表示」を押せば制限なしで送る。

Android は同じ署名の版の下げを、データを残したまま行わせないのが通例であり（`adb install -d` などの例外がある）、この範囲で十分と判断する。

### 3.7 移行

起動時の `Settings.migrate()` で、`externalPolicy` がなければ `blockExternalLocation` から作る。
`onlineVenues` の移行（今のコード）を先に行う。

| 送信先 | `blockExternalLocation` が true、または値がない（今の既定） | false |
| --- | --- | --- |
| `ofm`、`gsi`、`custom` | 操作時のみ、制限なし | 自動、制限なし |
| `geocoder` | 送信しない | 自動、正確 |
| `overpass` | 操作時のみ、正確、全インスタンス | 同左 |
| `data` | 自動、区画 | 同左 |

- 新規の利用者は左列になる。今の既定と同じである。
- `blockExternalLocation` が壊れている（型違い）場合は、今の `MapConsents.load` と同じく左列とし、同意を捨てる。
- `mapConsents` は `MapConsents.load` と同じ規則で読み、精度「制限なし」の同意として `externalConsents` に移す。
- `data` の「区画」は地域データの機能とともに入る。地域データの取得は操作でだけ始まるため、移行の時点で新たな送信は起きない。
- 「動作を変えない」の根拠は、次の同値性の試験とする（[8.1 節](#81-core-の単体試験jvm)）。旧設定の 2 通りから作った `Policy` について、新しい判定が今の判定と一致することを、判定の関数だけでなく、待機中の静止画、再試行を待つ取得、再起動の後に読み戻した同意、画面の外に出た地図、停止した作業の状態を含めて確かめる。

## 4. SendGate と送信の契約

### 4.1 状態

| 状態 | 今 | 変更後 |
| --- | --- | --- |
| 設定 | `blocked: Boolean` | `policy: Policy` と `paused: Boolean` |
| 世代 | 全体で一つの `gen` | 送信先ごとの `gens: Map[Dest, Long]` |
| 票（ticket） | `Long` | 送信先ごとの世代の写し（`Ticket(gens)`） |
| 許可（grant） | 表示 → 世代 | 表示 → （送信先、その世代） |
| 同意 | 地図の画面 → 地図 | 地図の画面 → （地図、送信先、精度） |

送信先ごとに世代を分けるのは、Geocoder の設定を変えたときに、表示中のオンライン地図の許可や待機中の静止画まで取り消さないためである。

### 4.2 送信の許し（Permit）

外部へのすべての要求は、要求を作った時点の **許し** を持つ。

```scala
enum Mode:
  case OnAction, Auto

/** 要求を作った時点の送信先、その世代、操作か自動か、精度。 */
final case class Permit(dest: Dest, gen: Long, mode: Mode, level: Level)
```

許しが有効であるのは、次をすべて満たす間である。

- `paused` でない。
- 送信先の規則の時機が、`mode` が `Auto` なら `Auto`、`OnAction` なら `Never` でない。
- 送信先の世代が `gen` と等しい（規則が、精度だけの変更を含めて変わっていない）。

許しは次の時点で確かめる。

1. 送信の直前（接続を開く前、`Geocoder` を呼ぶ前）。
2. 再試行のたび（`SendGate.firstSuccess` の次のホスト、`ResumableDownload` の再要求、WorkManager の再実行）。
3. リダイレクトのたび。自動のリダイレクトは使わず（`setInstanceFollowRedirects(false)`）、送信先ごとの許可されたホストの一覧に転送先が含まれ、許しがまだ有効な場合だけ従う。GitHub の転送先のホスト名は、実装の時に確かめて一覧に固定する。
4. 応答の受信中。許しが無効になった時点で接続を切る（[4.4 節](#44-outbound)）。

精度を下げる処理（`Precision.snap`、問い合わせの組み立て）は許しの `level` に従い、送信の直前に、送る値がその粒度であることを確かめる。

### 4.3 SendGate の API

```scala
final class SendGate(initial: Policy, initialConsents: Map[String, Consent],
                     persist: (Policy, Map[String, Consent]) => Unit):
  def policy: Policy
  def rule(d: Dest): Rule
  /** 規則を変える。変わった場合は d の世代を進め、d の許可と同意を消し、保存し、
    * listener に d を伝える。精度だけの変更でも同じ。 */
  def setRule(d: Dest, r: Rule): Boolean
  /** 一時停止の開始と解除。どちらでも全送信先の世代を進める。 */
  def setPaused(p: Boolean): Boolean
  def onChange(f: Set[Dest] => Unit): () => Unit

  def permit(d: Dest, mode: Mode): Option[Permit]   // 今の規則で許されなければ None
  def valid(p: Permit): Boolean

  def remember(surface: String, map: String, d: Dest): Unit  // d が OnAction の場合だけ
  def forget(surface: String): Unit
  def consent(surface: String): Option[Consent]               // その送信先が OnAction の間だけ
  def grant(owner: AnyRef, p: Permit): Unit
  def revoke(owner: AnyRef): Unit
  def online(owner: AnyRef, d: Dest): Boolean
  def networkAllowed: Boolean
```

- `block`、`setBlock`、`switchOn`、`blockFor` は移行の間だけ残し、呼び出し元を移した後に消す。
- 同意は、与えた時点の精度を持つ。規則の変更は精度だけの変更でも同意を消すので、精度を上げた後に古い同意で送ることはない。

### 4.4 Outbound

アプリが自分で HTTP で通信する箇所（Overpass、データの取得、同期のオフライン地図の確認）は、すべて `Outbound` を通す。

```scala
object Outbound:
  /** p が有効で、url のホストが p.dest の許可されたホストの場合だけ接続を開く。
    * 接続は p.dest ごとに登録し、p が無効になった時点で切る。 */
  def open(p: Permit, url: String): HttpURLConnection
```

- 接続の登録は、`SendGate.onChange` で、変わった送信先の接続をすべて `disconnect` する。
- リダイレクトは `open` の中で一つずつ確かめる（[4.2 節](#42-送信の許しpermit)）。
- 同期（`SyncClient`）は対象外とする。同期の設定が制御する。

**Geocoder** は OS の API の呼び出しであり、`open` では包めない。

- 呼び出しの直前に許しを確かめる。
- 呼び出しは一つの専用のスレッドに直列にし、同時に OS に渡す問い合わせを一つに限る。
- OS に渡した後の問い合わせは取り消せない。取り消しの限界は、規則の変更の時点で実行中の 1 件である。
- 呼び出しから戻った時点で許しが無効なら、答えを捨て、保存しない。

**MapLibre** は `HttpRequestUtil.setOkHttpClient` で interceptor を挟む。

- 要求の URL を送信先の URL の型（ホストとパスの先頭）と照合する。どれにも当たらない要求は拒む。
- カスタムの URL が組み込みの地図と同じホストを指す場合は、パスの型で区別し、区別できない場合はより厳しい規則を当てる。
- アプリが作るスタイルは、タイル、フォント、スプライトの URL に印のパラメータ（例 `ashidori-g=<世代>`）を付ける。interceptor は印を取り除いてから送り、印の世代が送信先の現在の世代でない要求を拒む。印は端末の外に出ない。OpenFreeMap のスタイルと TileJSON は、取得した後に端末内で書き換えて印を付ける（[4.7 節](#47-判定の関数と精度の適用)）。
- タイルの URL から z を読み、規則の精度の上限を超える要求を拒む。
- どの表示の要求かは区別できない。表示ごとの同意の検査は一段目（判定）に残る。

### 4.5 一時停止

一時停止は、地図、地名、施設の検索、データの取得への送信をまとめて止める。

- 規則は書き換えない。停止の間は、すべての送信先を「送信しない」として判定する。
- 開始と解除のどちらでも、全送信先の世代を進める。停止の前に作った許しと票は、解除の後も無効である。
- 開始の時点で、`Outbound` の接続をすべて切り、MapLibre の待機中の要求は世代の印で拒み、データの取得の WorkManager の作業と、予約した再試行を取り消す。
- 解除しても、操作による送信は再開しない。自動の処理は規則に従って新しい許しで始める。データの取得は、規則が自動なら改めて予約する。
- 同期、OS の測位、他のアプリへの受け渡しは止めない。名前と画面の 1 行でこれを示す（[5.2 節](#52-データの扱い)）。

### 4.6 三つの防御線

1. **判定**：判定の関数が、送ってはいけない場合に端末内のスタイルを選び、要求そのものを作らない。今と同じく、これが主である。
2. **MapLibre の通信可否**：`MapLibre.setConnected` をプロセス全体に効かせる。今と同じく補助である。
3. **送信の直前の確認（新規）**：`Outbound`、Geocoder の直前の確認、MapLibre の interceptor（[4.4 節](#44-outbound)）。

### 4.7 判定の関数と精度の適用

`BaseMapPolicy` の引数を `block: Boolean` から、地図の送信先の規則に変える。

| 関数 | 今 | 変更後 |
| --- | --- | --- |
| `interactive` | `block` が false なら選んだ地図、true なら同意した地図 | 選んだ地図の送信先が Auto なら選んだ地図、OnAction なら同意した地図、Never ならオフライン地図 |
| `snapshot` | `block` が false なら選んだ地図 | 選んだ地図の送信先が Auto なら選んだ地図、ほかはオフライン地図 |
| `thumbnail` | `block` が false なら描画 | 候補ごとに、その候補の送信先が Auto の場合だけ、その精度の上限で描画する。ほかは同梱の見本 |
| `offerAlternatives` | `block` かつ地図なし | 「オンライン地図で表示」の地図の送信先が OnAction かつ地図なし |
| `detailMap` | 選んだ地図、なければ最後のオンライン地図 | 加えて、送信先が Never の地図を除く。すべて Never なら None |

サムネイルは、選んだ地図の送信先だけでなく、各候補の送信先へ表示範囲を送る。
各候補の規則で判定するので、自動を許していない送信先へは送らない（[未決 17](#9-未決の事項)）。

精度は次の関数で適用する。

- `Precision.snap(lat, lon, gridDeg): (Double, Double)`：固定の格子の区画の中心を返す。Geocoder と Overpass の「地区」「地域」で使う。
- `Precision.maxZoom(level): Option[Int]`：地域は 12、地区は 15、制限なしは None。
- `TileStyle.capped(style, maxZoom, gen)`：スタイルのすべてのソースの `maxzoom` を上限以下にし、URL に世代の印を付ける。ラスタ（地理院、カスタム）はアプリが JSON を作る。OpenFreeMap はスタイルの URL を直接 MapLibre に渡しているため、スタイルと TileJSON を先に取得し（座標を含まない）、ソースを `tiles` と `maxzoom` を持つ形に書き換えて端末に置く。

### 4.9 形式検証

[`formal/README.md`](../../formal/README.md) が将来の課題に挙げる `SendGate` の TLA+ モデルを、送信先ごとの世代と許しで作る。
タイルの送信先 2 つ（同じホストのカスタムを含む）、Geocoder 1 つ、表示 2 つ、静止画の待ち行列、再試行、リダイレクト、一時停止を含め、次を検査する。

- 送信先 d への送信は、その時点で有効な d の許しを持つ場合だけ起きる（自動、操作、再試行、リダイレクトのすべて）。
- 表示が送信先 d へ送るのは、d が Auto か、その表示が d の現在の許可を持つ場合だけ（別の表示の許可で送らない）。
- Never の送信先へは、操作による送信も含めて送らない。一時停止の間はどこへも送らない。
- 一時停止の解除の後に、停止の前の許しで送らない。
- 送信先 d の規則の変更は、d と異なる送信先の許可と票を無効にしない（取り消しすぎない）。
- Geocoder は、規則の変更の時点で OS に渡していた 1 件を除き、変更の後に古い許しで送らない。

## 5. 画面の流れ

### 5.1 設定の入口

設定の「プライバシー」のスイッチ「オンライン地図と地名検索」を、行「データの扱い」に置き換える。
行の補足は送信を許す送信先の数とする（例「外部への送信 2 件を許可」、一つもない場合は「外部への送信なし」、一時停止の間は「外部への送信を停止中」）。

### 5.2 データの扱い

画面案の画面 5 に合わせる。
設定の結果を ✓ ／ ⊖ の一覧で示し、段落の説明は置かない。

```
← データの扱い

保存先
  ✓ この端末                       812 MB
  ✓ 同期サーバ                     暗号化して送信 · 最終 5分前   ›

外部への送信                       ✓ 許可  ⊖ 送信しない
  地図・検索への送信を停止                                    [  ]
  同期、位置の取得、他のアプリは対象外
  ✓ オンライン地図（OpenFreeMap）   表示範囲 · 操作時のみ          ›
  ✓ オンライン地図（地理院タイル）  表示範囲 · 操作時のみ          ›
  ⊖ オンライン地図（カスタム）      未設定                        ›
  ⊖ 地名検索                        滞在地・他の端末の位置        ›
  ✓ 施設のオンライン検索            位置 · 操作時のみ              ›
  ✓ 地図・施設データの取得          選んだ区画 · GitHub            ›
    位置の取得                      OS の設定による               ›
```

- ✓ は送信の **許可** を示し、今送信していることは示さない。⊖ は送信しない。見出しの右に凡例を置く。
- 記号の形で状態を示し、色だけに頼らない。✓ の記号は、今の送信の操作と同じ tertiary の色にする。
- 2 行目は「何を · いつ」とし、精度が制限なしでない場合は精度を付ける（例「表示範囲（約 1 km）· 自動」）。
- 地名検索の 2 行目は、送信しない間も送る対象（滞在地・他の端末の位置）を示す。許可の間は「滞在地・他の端末の位置 · 自動」とする。
- 一時停止のスイッチは「地図・検索への送信を停止」とし、対象外を 1 行で示す。停止の間は各行の ✓ を ⊖ の表示にし、2 行目を「停止中」とする。
- 「位置の取得」は OS の測位の参照であり、アプリが送信を制御しないので記号を付けない。[未決 5](#9-未決の事項) の結論まで表示だけにする。
- 設定を読み込めない場合（[3.5 節](#35-既定値復旧値読み込みの順序)）は、見出しの下に error の色で「設定を読み込めません（送信を停止中）」を出す。

### 5.3 送信先の詳細

行を押すと、その送信先の画面を開く。
選択肢は 2 群のラジオボタンと、送信先のホストの 1 行だけとする。

```
← オンライン地図（地理院タイル）

送信
  ○ 送信しない
  ● 操作時のみ
     表示を許した地図は、戻すまで保持
  ○ 自動

精度
  ○ 地域 約 10 km      [格子の凡例]
  ○ 地区 約 1 km       [格子の凡例]
  ● 制限なし           [格子の凡例]

送信先  cyberjapandata.gsi.go.jp

                         [キャンセル]  [適用]
```

- 2 群の変更は「適用」でまとめて一つの規則として保存する。適用するまで、規則も送信も変わらない。時機を先に選んでも、精度を選ぶ前に制限なしで送る中間の状態はない。
- 「適用」は変更がある間だけ有効にする。変更を残したまま戻る場合は、変更を捨てる。
- 「送信しない」の間も精度の群は選べる。次に許可するときの精度を先に決められる。
- 精度の凡例は、地図の上の格子と、送る座標の粒度の区画の塗りで示す（画面案の凡例と同じ）。
- 施設のオンライン検索は、精度の下に「検索先」としてホストごとのスイッチを置き、運営者が同じホストはまとめて示す。すべてオフは選べない（その場合は「送信しない」を選ぶ）。
- カスタムは「送信先」の行に URL のホストを出し、押すと今の URL の入力を開く。
- 地名検索は「送信先」の下に「対象  滞在地・他の端末の位置」の 1 行を置く。
- 適用の後、待機中と実行中の処理はその時点で新しい規則に従う（[4.2 節](#42-送信の許しpermit)）。

## 6. オフラインの地域データ

### 6.1 現状

| 項目 | オフライン地図 | 施設データ |
| --- | --- | --- |
| 内容 | 日本（ズーム 6〜10、`japan.pmtiles`）と全世界（ズーム 0〜5、`world.pmtiles`）、スタイル、フォント、スプライト | 日本の施設 1,073,493 件（`venues.aven`） |
| 大きさ | 約 64 MB（archive 63,591,472 バイト） | 約 18 MB |
| 作り方 | `tools/basemap/build.sh`：Protomaps の日次ビルド（`https://build.protomaps.com/<日付>.pmtiles`）から go-pmtiles の `extract` で切り出す | `tools/venues/build.sh`：Geofabrik の日本の抽出から pyosmium で抜き出す |
| 配布 | GitHub Releases（タグ `basemap-<版>`）、同期サーバ（R2） | GitHub Releases（タグ `venues-<版>`） |
| 完全性 | APK に固定した大きさと sha256（`basemap-pin.json`） | 同じ（`venues-pin.json`） |
| 端末 | `filesDir/basemap/<版>/`（`BasemapStore`）、`PinnedDownload` が Range で再開する | `filesDir/venues/<版>/` |

スタイルは二つのソースを重ね、日本を全世界の上に、文字をすべての図形の上に置く（`tools/basemap/assemble.py` の `layers`）。
MapLibre は `pmtiles://file://` のソースを端末内で読んでおり、PMTiles の読み込みはこのアプリで動作を確かめた形式である。

起動時には `AshidoriApp.scala:44` 以降が `Basemap.cleanup()` と `VenueData.cleanup()` を呼び、固定した版以外をすべて消す。
地域データはこの掃除を流用しない（[6.7 節](#67-保存と復旧)）。

### 6.2 要件

- 地図の上の固定の枠に地図を動かして範囲を合わせ、大きさを 1 行で示す（画面案の画面 6）。
- 取得済みの一覧に、名前、大きさ、取得日、︙（更新、名前を変更、削除）、新しい版の印を示す。期限は設けない（画面案の画面 7）。
- 取得したデータは改ざんを検出できる（sha256）。
- 取得は中断しても再開でき、どの時点で止まっても一貫した状態に戻る。
- 既定では従量制でない回線を待つ。
- 地域データの取得で伝わる情報と、自動更新の有無を、取得の前に画面で示す。
- 取得と配置が記録の領域を使い切らない。

### 6.3 方式の比較

| 方式 | 配信元に伝わる範囲 | 端末の負担 | 完全性 | 配信元の負担 | 評価 |
| --- | --- | --- | --- | --- | --- |
| A. 固定の区画ごとのパックを静的ファイルで配る | 選んだ枠を含む区画の集合（約 130 km 四方の単位）と、その組み合わせ、順序、履歴 | 区画が枠より広い分だけ大きい。展開なし | ファイルごとの sha256 | 静的ファイルのみ | **採る** |
| B. 大きな archive（日本全体の詳細）を取得し、端末で使う | 細かな選択の範囲は送らない。日本全体を取得した事実と IP アドレスは伝わる | 未計測。数 GB と見込むが根拠はない。端末で切り出すなら一時的に 2 倍の容量 | archive の sha256 | 大きなファイル 1 つ（2 GiB を超えるなら分割） | 計測の後に、A に加える選択肢として決める（[未決 8](#9-未決の事項)） |
| C. 端末から大きな PMTiles へ Range 要求を送り、枠の分だけ切り出す | 枠そのもの。要求するバイト範囲がタイルの番号に対応するため、配信元は範囲を復元できる | 要求の数が多い | 切り出した部分は archive の sha256 で照合できない。タイルごとの署名つき一覧が別に要る | 細かい Range 要求が多数 | 採らない |
| D. MapLibre の機能でオンライン地図の配信元からタイルを一括取得する | 枠そのもの（タイル単位） | タイル数が多い（ラスタ） | なし | 配信元にタイルの一括取得を課す。各配信元の利用条件は確かめていない | 採らない |

A を採る理由は次のとおりである。

- 伝わる範囲が区画の単位に粗くなる。枠の位置そのものは送らない（組み合わせなどからの推測は [7.1 節](#71-設定ごとに伝わるもの)）。
- 今の配布の仕組み（静的ファイル、大きさと sha256 の固定、Range での再開、検証の後の原子的な配置）を使える。
- 区画は複数の地域で共有でき、重複して取得しない。

### 6.4 区画

区画は、Web メルカトルのズーム 8 のタイルとする（識別子 `8-<x>-<y>`）。

- 1 辺は北緯 35° で約 128 km であり、緯度が高いほど縮む。
- PMTiles のタイルの番号と揃うので、区画の内側のタイルはズーム 8 以上で区画の外にはみ出さない。隣の区画とタイルが重ならない。
- `tools/basemap/japan.geojson`（長方形の集まり）と交わるズーム 8 の区画は 136 個である（海だけの区画を含む。本書の作成時に数えた）。
- パックはズーム 8〜15 の、その区画の内側のタイルを持つ。タイル数は最大 21,845 である。Protomaps の公開ビルドの最大ズームは 15 である。
- パックの大きさは計測していない。都市部と山間部で大きく異なると見込む。区画ごとの大きさは、最初の作業として日本の全区画で測る。

### 6.5 パック、スタイルの束、カタログ

| ファイル | 内容 |
| --- | --- |
| `ashidori-region-8-<x>-<y>-<版>.pmtiles` | 区画の地図（PMTiles v3、ズーム 8〜15）。zip に包まない |
| `ashidori-venues-8-<x>-<y>-<版>.aven` | 区画の施設データ（日本の外の区画だけ。[6.13 節](#613-施設データ)） |
| `ashidori-regions-style-<スタイル版>.zip` | パックの層の雛形、フォント、スプライト。パックの文字列の文字の範囲を含む |
| `ashidori-regions-<版>.json` | カタログ：区画ごとのファイル名、大きさ、sha256、範囲、ズーム、ビルドの日付、スタイル版、施設の件数。スタイルの束の大きさと sha256 |

カタログの例を示す。

```json
{"format":"ashidori regions catalog v1","version":"20261201","build":"20261201",
 "minzoom":8,"maxzoom":15,
 "styles":[{"style":"s1","file":"ashidori-regions-style-s1.zip","bytes":2345678,"sha256":"…"}],
 "cells":[
  {"cell":"8-227-100","style":"s1",
   "map":{"file":"ashidori-region-8-227-100-20261201.pmtiles","bytes":123456789,"sha256":"…"},
   "venues":null}
 ]}
```

- パックはスタイル版を持ち、同じスタイル版の束で描く。束はオフライン地図の archive から独立させる。オフライン地図の版の更新とパックの版がずれても、パックの描画は変わらない。
- スタイル版は Protomaps の層の定義（`@protomaps/basemaps` の版）とフォントの範囲で決める。パックの版が変わってもスタイル版が同じなら、束は取得し直さない。

完全性は二段で確かめる。

1. APK はカタログの大きさと sha256 を固定する（`regions-pin.json`、今の `BasemapPin` と同じ形式）。カタログの取得は座標を含まない。
2. パックとスタイルの束はカタログの大きさと sha256 で照合する。照合の後に PMTiles のヘッダを読み、範囲が区画の内側に、ズームがカタログの値に収まることも確かめる。

この形では、データの更新はアプリの版の更新とともに届く（今のオフライン地図と同じ）。
アプリと独立にデータを更新するための署名つきのカタログは、[未決 6](#9-未決の事項) とする。

配布は GitHub Releases のタグ `regions-<版>` とする。
1 リリースあたり 1,000 アセット、各ファイル 2 GiB 未満の上限に収める。
日本の区画だけなら、地図のパックは 136 個以下である。
2 GiB を超えるパックが出た場合は、その区画をズーム 9 の 4 区画に分ける。

### 6.6 地域とパックの関係

利用者が名前を付けて管理する単位を **地域**、取得の単位を **パック** とする。

- 地域は名前と区画の集合を持つ。枠で選んだ範囲が複数の区画にかかれば、その地域は複数のパックを参照する。
- 参照数は保存せず、地域の区画の集合から毎回求める。保存した数と実際がずれることがない。
- 地域の大きさは、その地域が参照するパックの合計とする。他の地域と共有するパックも含める。
- 地域の名前の既定値は、枠の中心の地名を端末内の索引で求めたもの（例「つくば市周辺」）とする。索引で求まらない場合は「地域 1」のように番号を付ける。Geocoder は使わない。

### 6.7 保存と復旧

```
filesDir/regions/
  state.json                         地域（名前、区画）、各パックの状態と版、取得日
  packs/<cell>/<版>/map.pmtiles      完全なパック（検証の後の改名で現れる）
  packs/<cell>/<版>/venues.aven
  styles/<スタイル版>/               スタイルの束を展開したもの
  .download/<file>.part              取得中のファイル
```

**書き込みの順序**：

1. 利用者の操作の時点で、`state.json` に地域と、取得するパックを「予定」として書く（一時ファイルと改名）。
2. パックを `.download/` に取得し、sha256 とヘッダを確かめる。
3. ディレクトリの改名で `packs/<cell>/<版>/` に置く。
4. `state.json` のそのパックを「取得済み」にする。

**起動時の照合**（地域データ独自の処理。`Basemap.cleanup()` は流用しない）：

- 3 と 4 の間で止まった場合、パックのディレクトリはあるが状態は「予定」である。ディレクトリは検証の後にだけ現れるので、「取得済み」に直す。
- 2 で止まった場合、`.part` を残し、次の取得で続きから取得する（大きさが揃っていれば検証から再開する）。
- 状態にない区画のディレクトリ、どの地域も参照しない版は、削除の候補とする。
- 状態を読めない場合は、ディレクトリの走査から「取得済み」のパックを復元し、地域は区画ごとに一つずつの仮の地域として作り直す。データを消さない。

**使用中のファイルを消さない**：

- スタイルは作るたびに番号を持つ。地図と静止画は、読み込んだスタイルの番号を登録し、別のスタイルに替えるか破棄した時点で解除する。
- 削除と更新は、新しいスタイル（そのパックを含まない、または新しい版を含む）を全地図に適用した後、古い番号を参照する地図と静止画がなくなってから古いファイルを消す。
- 消せなかったファイルは `state.json` の削除の待ちに残し、起動時と参照の解除の時に処理する。

**版の保持**：

- 更新では、新しい版の検証と配置が済むまで古い版を残す。通信できない場所で更新が失敗しても地図は消えない。
- スタイルの束は、取得済みのパックが一つでも参照する版を残す。

**記録のデータベースとの分離**：状態は記録のデータベースに入れず、`state.json` に書く。地域データの処理が記録のデータベースの書き込みと競合しないためである。

### 6.8 容量の予算

256 MB は監視の閾値であり、予約された領域ではない。
他の大きな書き込みが同時に動けば、閾値を確かめた後に空きが減りうる。
記録の領域を実際に守るため、アプリの大きな書き込みは共通の予算（`StorageBudget`）を通す。

- 対象は、オフライン地図と施設データの取得と展開、地域データのパックとスタイルの束の取得と展開、バックアップの書き出しの一時ファイル（`VACUUM INTO` の複製）である。
- 書き込みの前に、書く予定のバイト数を予約する。予約は `空き容量 − 予約済みの合計 − 記録の予備 ≥ 要求` の場合だけ通る。
- 記録の予備は 256 MB（`Backup.LoggingMargin`）を下限とし、現在の記録モードの 24 時間分の見込みが大きければそちらとする。
- 書き込み中も空きを確かめ、予備を下回れば中断する。予約は完了か中断で返す。
- 大きな書き込みは一度に一つに限る（予約を直列にする）。
- 他のアプリによる容量の消費は防げない。予算が守るのは、このアプリの重い処理が記録の領域を使うことである。

### 6.9 取得

- WorkManager の一意の作業（`regions-download`）が、待ち行列のパックを 1 つずつ取得する。今の `PinnedWorker` と同じく、`ResumableDownload`（Range での再開）と `DownloadRetry` を使い、`Outbound` を通す。
- 作業は予約の時点の許し（`data`、操作か自動か）を持ち、実行と再試行のたびに確かめる（[4.2 節](#42-送信の許しpermit)）。
- 既定では従量制でない回線を待つ（`regionsMetered` が false）。モバイルデータ通信の場合は、今のオフライン地図と同じ確認の画面を出す。
- 取得の要求は端末のトークンもクッキーも持たない。User-Agent は今と同じ `ashidori/<版>` とする。
- 取得の順序は、選んだ順でも中心からの順でもなく、区画の識別子の順とする。順序から選択の中心を推測させないためである。

### 6.10 地図への組み込み

端末内のスタイルは、今のスタイルに取得済みのパックのソースを加えて作る。

- パックごとにソース `r-8-<x>-<y>`（`pmtiles://file://…/map.pmtiles`、`minzoom` 8、`maxzoom` 15、`bounds` は区画）を加える。
- 層は、パックのスタイル版の雛形を、パックのソースの名前で複製する。順序は「全世界の図形、日本の図形、パックの図形、全世界の文字、日本の文字、パックの文字」とし、今の `assemble.py` の重ね方に従う。
- フォントとスプライトは、パックの層ではスタイルの束のものを使う。MapLibre のスタイルの `glyphs` は一つしか指定できないため、束のフォントはオフライン地図のフォントの範囲を含む上位の集合とし、パックがある場合は束のフォントを `glyphs` にする。
- 区画の内側では、パックの図形がオフライン地図の図形を覆う。文字の重なりは MapLibre の衝突の判定に任せる。区画の境界と、ズーム 8〜10 で日本のソースと重なる部分の見た目は実機で確かめる。
- ソースの数が増えると描画の負担が増える。パックの数の上限（例 16）を設け、実機で測ってから決める。上限を超える使い方が要る場合は、端末で複数のパックを一つの PMTiles に合成する方式を検討する（[未決 11](#9-未決の事項)）。
- パックの追加と削除でスタイルを作り直し、表示中の地図に読み込み直させる（[6.7 節](#67-保存と復旧)）。スタイルの照合（`OfflineBasemapStyle.remoteUrls` が空）は今と同じく行う。

```
   180 MB · 空き 41.2 GB
   GitHub に伝わる範囲: 区画 2 個
   [✓] Wi-Fi 接続時に自動更新

   [キャンセル]          [ダウンロード]
```

- 枠は画面に固定し、利用者は地図を動かし拡大縮小して範囲を合わせる。
- 枠と交わる区画を地図に薄い線で示す。取得するのは枠ではなく区画であり、その区画が配信元に伝わる。
- 大きさはカタログの値の合計であり、見積もりではない。取得済みの区画は除く。予算（[6.8 節](#68-容量の予算)）に収まらない場合は、ダウンロードを無効にし「空き容量が不足」と出す。
- 自動更新の有無はこの画面で選ぶ。初回の既定はオンで、前回の選択を引き継ぐ。`data` が「操作時のみ」の場合は、この行を出さない。
- 区画が上限（例 4 個）を超える縮尺では、「範囲を狭めてください」と出し、ダウンロードを無効にする。
- カタログにない区画（日本の外など）は灰色にし、合計に含めない。
- 入口は、地図のタブの ︙ の「地図をダウンロード」と、「オフラインのデータ」の「＋ 範囲を選んで取得」とする。

### 6.12 管理の一覧と更新

画面案の画面 7 に合わせ、「オフラインのデータ」とする。
今の「オフライン地図」と「施設データ」の行も、同じ部品でこの一覧に入れる。

```
← オフラインのデータ                     ＋ 範囲を選んで取得

  ✓ 関東                新しい版     412 MB · 2026/10/13   ⋮
  ✓ つくば周辺                        38 MB · 2026/11/02   ⋮
  ↓ 香港                              取得中 · 38%          ⋮
  ✓ オフライン地図 · 全域             64 MB · 2026/10/13   ⋮
  ✓ 施設データ · 日本                 18 MB · 2026/10/14   ⋮

  自動更新                            Wi-Fi 接続時          ›
```

- 状態は先頭の記号で示す（✓ 取得済み、↓ 取得中・待機中、! 失敗）。失敗は error の色の 2 行目に理由を出す。
- 取得日は、その地域のパックを最後に取得した日とする。
- 「新しい版」の印は、地域のパックのどれかについて、APK のカタログの版が端末の版より新しい場合に出す。
- ︙ は「更新」「名前を変更」「削除」とする。「更新」は新しい版がある場合だけ有効にする。「削除」は、他の地域と共有しないパックだけを消すことを確認の画面の 1 行で示す。
- 期限は設けない。古い版も削除されるまで使える。
- 自動更新（`regionsAutoUpdate`）は、新しいカタログを持つアプリに更新された後、取得済みの区画の新しい版を取得する。`data` が「自動」の場合だけ動き、「操作時のみ」では一覧の「更新」でだけ更新する。
- 「モバイルデータ通信でも取得」（`regionsMetered`、既定オフ）は、自動更新の行の先の画面に置く。

### 6.13 施設データ

- 日本は今の施設データ（日本全体で約 18 MB）をそのまま使う。区画に分けても伝わる範囲が粗くなるだけで、大きさの利点が小さいためである。
- 日本の外の区画は、地図と同じ区画で施設データのパックを作る。地域を取得すると、地図と施設のパックを合わせて取得する。
- `VenueData` は今は索引を一つだけ開く。区画の索引を複数開き、検索の位置に交わる索引だけを引くように変える。`VenueIndex` の AVEN 形式は格子の原点と大きさを持つので、形式は変えずに区画ごとに作れる。
- 施設の名前での検索（`VenueData.search`）は、取得済みのすべての索引を引き、距離で並べる。

### 6.14 外部送信の設定との関係

- 地域データの取得は、`data` が「区画」で「送信しない」でなく、一時停止でない場合だけ使える。「全域のみ」では「＋ 範囲を選んで取得」を出さない。
- 範囲の選択とダウンロードの操作を、区画を送る同意とする。取得の画面に「GitHub に伝わる範囲: 区画 N 個」を出す。
- 同期サーバからは地域データを取得しない（[未決 9](#9-未決の事項)）。
- 地域データは端末内のデータなので、取得済みの範囲の表示は外部への送信の設定に関係なく使える。
- オンライン地図に精度の上限（地区、地域）がある場合、上限より拡大した部分を地域データで描く組み合わせは、後の課題とする（[未決 12](#9-未決の事項)）。

### 6.15 ツール

今のツールでできること：

- `tools/basemap/build.sh` は、Protomaps の日次ビルドから go-pmtiles 1.31.2 の `extract`（`--region`、`--minzoom`、`--maxzoom`）で切り出す。ビルドの全体を取得せず、Range 要求で必要な部分だけを読む。
- `tools/basemap/assemble.py` は PMTiles v3 を読み、文字列の文字の範囲を集め、層とフォントとスプライトを組み立てる。
- `tools/basemap/package.sh`、`release.sh` は archive、記述子、APK の固定値、公開のコマンドを作る。
- `tools/venues/build.sh`、`build_index.py` は Geofabrik の抽出から AVEN の索引を作る。

新たに要るもの：

## 7. 脅威とプライバシーの分析

### 7.1 設定ごとに伝わるもの

| 設定 | 受け取る者 | 伝わるもの | そこから推測できること |
| --- | --- | --- | --- |
| オンライン地図、操作時のみ | 選んだ地図の配信元 | 同意した画面で表示した範囲のタイル番号（精度の粒度）、要求の順序と時刻、IP アドレス | 関心のある地域。現在地の近くを表示する習慣があれば現在地 |
| オンライン地図、自動 | 各地図の配信元 | 加えて、フィード、期間、他の端末の静止画の範囲（過去の日の経路と滞在地を収める範囲）。サムネイルでは各候補の配信元に現在の表示範囲 | 自宅、職場、移動の範囲、他の端末の所在 |
| オンライン地図、地域・地区 | 同上 | タイル番号の粒度がズーム 12、15 になる | 粒度は粗くなるが、隣り合うタイル、順序、時刻、画面の大きさから細かく推測しうる（[3.2 節](#32-精度の意味)） |
| オンライン地図（カスタム） | 入力した URL のホスト | 上記と、URL の API キー | 上記が、配信元の利用者アカウントと結び付く |
| フォントの要求 | 地図の配信元（OpenFreeMap） | 表示する文字の範囲 | 表示した地域の文字の種類（例：ハングル、アラビア文字）。座標は直接含まない |
| 地名検索、自動 | Geocoder の実装の提供者 | 索引で求まらない滞在地と、他の端末の現在地の座標（精度の粒度）、問い合わせの時刻 | 滞在した場所、他の端末の所在。提供者の側で端末やアカウントと結び付くかは未確認 |
| 施設のオンライン検索、操作時のみ | 有効にした Overpass のホスト（最大 4 ホスト、3 者） | 検索した位置（精度の粒度。地区では中央の 0.01° の区画）、時刻、IP アドレス、アプリの版 | その時刻にその場所付近にいたこと、または過去の訪問の場所 |
| データの取得、全域のみ | GitHub | 取得の時刻、IP アドレス、アプリの版、日本全体を取得したこと | アプリを使っていること、日本の地図を使うこと |
| データの取得、区画 | GitHub | 加えて、選んだ区画の集合 | これから行く地域、または関心のある地域。過去でなく未来の行動を示しうる。区画の組み合わせ（隣り合う 2 区画なら境界の近く）、追加と削除の履歴、再取得から、枠の位置を区画より細かく絞りうる |
| 自動更新 | GitHub | 同じ区画の再取得と時刻 | 区画への関心が続いていること。IP アドレスを通じて期間をまたいで結び付く |
| 出典のリンク | ブラウザで開く先 | 出典の URL。MapLibre の既定の画面では、URL によりカメラの位置 | アプリの出典の画面に置き換え、座標を付けない（[4.8 節](#48-呼び出し元の対応)） |
| 同期 | 同期サーバの運用者 | [`privacy.md`](../privacy.md) の表のとおり | 変わらない |

### 7.2 通信路の観察者

- 回線の事業者や Wi-Fi の運用者は、TLS の SNI と接続先の IP アドレスから、どの配信元に接続したかを知りうる（地理院タイルを使っている、Overpass に問い合わせた、など）。
- 地域データのパックは区画ごとに大きさが異なる。転送量から区画を推測されうる。詰め物（padding）で大きさを揃える対策は、容量の増加に見合わないので採らない。この残余は本書と `privacy.md` に記す。

### 7.3 精度の限界

- 精度は送る値の粒度であり、位置を隠す範囲の保証ではない（[3.2 節](#32-精度の意味)）。
- 固定の格子に丸めても、格子の境界を越えた時刻は伝わる。自動の送信を繰り返すと、区画の単位の移動の経路が伝わり、道路などの補助の情報と合わせて絞られうる。
- MapLibre は表示範囲の周囲や低いズームのタイルを先に読むことがあり、送る範囲は画面の範囲よりやや広い。
- 送信先を Never にしても、それ以前に送った情報は取り消せない。Geocoder は、変更の時点で OS に渡していた 1 件を取り消せない。MapLibre の端末内のキャッシュは、送信を伴わないので消さない。

### 7.4 この設定で守らないもの

- OS の測位サービス（Google 位置情報の精度）が送る情報。
- 利用者が他のアプリに渡したもの（`geo:`、共有）。
- 同期サーバの運用者に見えるメタデータ（別の文書で扱う）。
- 配信元の運営者が、IP アドレスを他の情報と結び付けること。
- 旧版のアプリに戻した場合の、[3.6 節](#36-旧版との互換) の反例の送信。

## 8. 試験の計画

### 8.1 core の単体試験（JVM）

- `Policy` の読み込み：重複したキー、送信先の重複、余分な項目（除いた後に正準形と一致すること）、未知の版、選べない組、欠けた送信先。破損と未知の版は復旧値になり、保存し直さないこと。利用者の変更で初めて上書きすること。
- 新規の導入の既定と復旧値が異なること。復旧値では、どの送信先も自動では送らないこと（`data` の自動の取得と自動更新も含む）。
- 移行：`blockExternalLocation` が true、false、値なし、型違いの 4 通りと、`onlineVenues` の有無の組み合わせ。`mapConsents` の引き継ぎ。
- 旧版向けの派生値：`blockExternalLocation` は旧設定のオフと一致する場合だけ false。`mapConsents` には精度「制限なし」の同意だけが入ること。
- 同値性：旧設定の 2 通りから作った `Policy` について、新しい判定が今の判定と一致すること。対象は判定の関数（地図の種類、同意、画面の表示、オフライン地図の有無の全組み合わせ）、静止画の待ち行列の待機中のジョブ、再試行を待つ取得、再起動の後に読み戻した同意、画面の外に出た地図、停止した作業である。
- 許し：規則の変更、精度だけの変更、一時停止の開始と解除で無効になること。他の送信先の変更で無効にならないこと。
- `Outbound`：送信の直前、再試行（`firstSuccess`、`ResumableDownload`）、リダイレクト（許可されていないホスト、途中で無効になった許し）のそれぞれで拒むこと。規則の変更で実行中の接続を切ること（偽の HTTP で確かめる）。
- MapLibre の interceptor（URL の照合の部分を core に置く）：未知のホストを拒む。同じホストのカスタムの URL を区別する。世代の印を取り除いて送り、古い世代を拒む。精度の上限を超える z を拒む。
- `Precision.snap`：格子の中心を返す。負の座標、180° 経線、極付近。同じ区画の点は同じ値になる。
- Overpass の問い合わせ：地区では区画の bbox だけを含み、元の座標を含まない（問い合わせ文字列に元の座標の桁が現れないことを確かめる）。
- `TileStyle.capped`：すべてのソースの `maxzoom` が上限以下になり、すべての URL に世代の印が付く。
- 地域データ：区画の計算（ズーム 8、境界、180° 経線）、枠と交わる区画、カタログの解析と検証、PMTiles のヘッダの範囲の検証、参照数の算出、書き込みの順序の各段で止めた後の起動時の照合、`state.json` を読めない場合の復元、使用中のファイルを消さないこと、スタイルの束の保持、取得の順序が区画の識別子の順であること、Range での再開と sha256 の不一致（今の偽の `RangeHttp` を使う）。
- 容量の予算：同時の予約、記録の予備の算出、書き込み中の中断、予約の返却。
- 合成したスタイル：`OfflineBasemapStyle.remoteUrls` が空であること。

### 8.2 形式検証

- `formal/tla/SendGate.tla`（[4.9 節](#49-形式検証)）を CI のパスに加える。
- 変異として、世代を全体で一つに戻した版で「取り消しすぎない」性質が破れ、再試行やリダイレクトで許しを確かめない版、一時停止で世代を進めない版で「有効な許しでだけ送る」性質が破れることを確かめる。

### 8.3 端末での試験

製品に組み込む前に必須とする。

- 通信の記録：デバッグ版で、`Outbound`、Geocoder の呼び出し、MapLibre の interceptor が扱うすべての要求の送信先、ホスト、パス、時刻を記録する。合わせて端末の外の HTTPS の中継で記録し、interceptor を通らない通信がないこと（MapLibre 自体の通信を含む）を確かめる。
- 次の筋書きごとに、記録が規則と一致することを確かめる。
  - 新規の導入：GitHub（オフライン地図、施設データ）以外へ送らない。
  - 旧設定 true と false からの更新：更新の前後で送信先と要求が変わらない。
  - 設定の破損：どこへも自動では送らない。
  - 地図だけ自動：静止画とサムネイルが送り、Geocoder へは送らない。サムネイルは Auto の候補の配信元にだけ送る。
  - Geocoder だけ地域：問い合わせの座標が 0.1° の格子の中心である。
  - 地図を地区：ズーム 16 以上でもズーム 15 を超える要求がない。
  - 規則の変更：待機中の静止画を捨て、実行中のものを中止し、変更の後に古い許しで送らない。
  - 詳細画面で時機と精度を順に変える：「適用」までは何も送らず、適用の後は新しい精度でだけ送る。
  - 一時停止：開始の時点で接続が切れ、データの取得の再試行が取り消される。解除の後に停止の前の要求が送られない。
  - リダイレクト：データの取得のリダイレクトが許可されたホストにだけ従う。
  - 再起動：同意と規則が保たれ、再起動の前の許しで送らない。
  - Overpass の一部のホストをオフ：そのホストへ送らない。
  - 出典の画面：座標を付けたリンクを開かない。
- 地域データ：機内モードで、取得した区画の内側をズーム 15 まで描き、区画の外ではオフライン地図に戻る。境界の見た目、文字の重なり、日本の外の文字、パックの数を増やしたときの描画の時間。
- 記録との独立：記録モード「最高精度」で記録しながら大きなパックとバックアップを同時に要求し、記録の欠落がなく、予算が書き込みを直列にし、記録の予備を下回る前に止まることを確かめる。
- 取得の中断：通信の切断、アプリの強制終了、端末の再起動を書き込みの順序の各段で起こし、起動時の照合で一貫した状態に戻ることを確かめる。

### 8.4 画面の確認

- 「データの扱い」の ✓ ／ ⊖ の一覧を、色を除いた表示（グレースケール）で読めること。
- TalkBack で、各行の状態（許可、送信しない）と時機が読み上げられること。
