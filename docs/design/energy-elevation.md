# 電池の計測と標高の記録（レビュー用）

> 状態：**実装済み、未レビュー**。ブランチ `energy-elevation-rebased`（0.21.0 の後の main が基点）。
> 容量の数値は、合成データを今の writer と sqlite3 で書いて測った値である。端末の実データでは測っていない。

## 目的

二つの記録を加える。

- **電池の計測。** 記録が電池をどれだけ使うかを、端末自身の記録から推定する（`EnergyModel`）。[自動モード](auto-mode.md) の前提になる。端末診断に結果を表示し、記録モードの説明の下に「実測」の 1 行を出す。
- **標高。** 気圧計と GNSS の海抜高度から、1 日の標高を推定する（`Elevation.estimate`）。今は状態タブに直近の海抜高度を出すだけで、推定はまだ画面に出していない。

どちらも記録と計算は端末の中で完結し、外部のサービスに何も送らない。

## 記録する内容と容量

| 表 | 内容 | 頻度 | SQLite | Parquet（gzip） |
| --- | --- | --- | --- | --- |
| `battery` の追加列 | 残量計（µAh）、平均と瞬時の電流、電圧、温度、給電の種類 | 5 分ごとと、状態が変わるたびに 1 行（行は従来どおり） | 1 行あたり約 30 B 増（推定） | 1 日 348 行で約 3.4 KB 増 |
| `energy_state`（新規） | 記録の状態の区間（下記） | 状態が変わるたびに 1 行。区間は 0 時で分ける | 1 行約 100 B（推定） | 60 行で約 1.4 KB |
| `fixes` の追加列 | `alt` の精度、海抜高度とその精度 | 測位ごと（行は従来どおり） | 1 Hz で 1 時間約 89 KB 増 | 1 Hz で 1 時間約 47 KB 増 |
| `pressure`（新規） | 気圧（hPa） | 移動中は 5 秒ごと、静止中は最大 1 分ごと（下記） | 移動中 1 時間約 27 KB | 移動中 1 時間約 2.8 KB |

`fixes` の追加分は乱数の精度で測ったので、実データより大きいと見込む。
状態の区間の数は使い方で決まり、1 日の典型的な数は測っていない。

### 記録の状態（`energy_state`）

次のどれかが変わるたびに、前の区間を閉じて新しい区間を開く。

- GNSS の要求の有無、要求間隔、登録した provider
- 生データ記録の有無、静止モードの有無
- 画面の点灯、充電（給電の接続）
- 利用者の記録モードと実際に効いているモード
- 動きの推定（`MotionState`）、屋内外の推定（`Environment`）

開いている区間（現在の状態）は `end` が NULL の行である。
プロセスが強制終了されると、区間は開いたまま残る。
次の起動時に、SQLite にある最後の電池の読みの時刻で閉じる。

### 気圧（`pressure`）

気圧計は wakeup でないセンサーとして 1 Hz で登録し、報告の遅延（移動中は加速度のバッチに合わせて 10〜60 秒、静止中は 60 秒）を長くとる。
センサーハブが読みを溜め、端末が起きたときにまとめて渡すので、気圧計のために端末を起こさない。
権限は要らない。

保存するのは間引いた系列である（`PressureDecimator`）。

- 移動中：5 秒ごとの中央値を 1 行。
- 静止中：1 分ごとの中央値を、前の行から 0.05 hPa 以上変わった場合か、10 分たった場合に 1 行。天気による変化は 1 時間に 0.1〜1 hPa 程度なので、静止した 1 時間は数行になる。

### 海抜高度（`fixes` の `msl`）

Android の高度は WGS84 の楕円体高である。
Android 14 以上では `AltitudeConverter` が端末内のジオイドモデルで海抜高度に換算し、その結果を `msl` と `msl_acc` に入れる。
換算に通信はない。
地域ごとの初回はモデルをプラットフォームの asset から読む（ディスク I/O）。
13 以下の端末では NULL である。

## 書き込みの経路

新しい行は、測位や動きと同じく `LoggerWrites`（記録専用のスレッド）で SQLite に書く。
UI の読み込み、書き出し、消費の推定（共有の I/O executor）を待たない。

- 種類ごとに `WriteKind` を持つ。キー（`energy_state`、`pressure`、`battery`）で数え、ラベル（「記録の状態」「気圧」「電池」）は表示だけに使う。文言を変えても数え方は変わらない。
- 書き込み待ちの上限、再試行、失った行の計上、保存の遅れの通知は、ほかの種類と同じである。ある種類が 3 分を超えて保存されなければ、ほかの種類が保存されていても通知する。
- 気圧は、センサーが一度に渡したバッチを処理した直後（ロガーのスレッドの次のメッセージ）に書き込みへ回す。メモリに残るのは、閉じていない 5 秒（静止中は 1 分）の区切りだけである。
- 状態の区間と電池の読みは、変化を検出したときにすぐ書き込みへ回す。

ファイルへの退避（overflow）は生データの行だけが持つ。
新しい種類は測位と同じ「小さい行」の上限（20 万行、SQLite に数日書けない場合にだけ達する）に入り、超えた分は失った行として数えて通知する。

## スキーマとマイグレーション

### SQLite

データベースの版を 6（0.21.0）から 8 に上げる。

| 版 | 内容 |
| --- | --- |
| 7 | `battery` に `charge_uah INTEGER`、`current_avg_ua INTEGER`、`current_now_ua INTEGER`、`voltage_mv INTEGER`、`temp_c REAL`、`plug TEXT` を追加。`energy_state(start, end, gnss, gnss_interval_ms, provider, detail, still, screen_on, charging, mode, eff_mode, motion, env)` と `start` の索引を作成 |
| 8 | `fixes` に `alt_acc REAL`、`msl REAL`、`msl_acc REAL` を追加。`pressure(time, hpa)` と `time` の索引を作成 |

- 追加だけである。列はすべて NULL を許し、既存の行は変えない。
- 各段は無い列と表だけを足す（`PRAGMA table_info` と `IF NOT EXISTS`）。同じ段を再度実行しても変わらない。
- 新規の作成は版 6 の作成に同じ段を続けるので、移行したデータベースと同じ表になる。
- SQL は `core` の `DbSchema` に置き、`DbMigrationSuite` が sqlite3 で試験する。0.21.0 と同じ文で作って行を入れたデータベースを 8 に移行し、行が変わらないこと、新規に作った表と列・索引が一致すること、再実行で変わらないこと、移行後の行の rowid が既存より大きいことを確かめる。
- `energy_state` と `pressure` は rowid の床（`rowid_floor`）の対象である。挿入は床から rowid を取る。
- 版を戻す手段はない。0.21.0 のアプリは版 8 のデータベースを開けない（Android の既定の `onDowngrade` が失敗する）。

### アーカイブ（Parquet）

`energy_state` と `pressure` は測位などと同じ信号の表（`Archive.SignalTables`）であり、次をすべて共有する。

- 日ごとの変換と、置き換えるファイルと消す行の記録（`CommitIntent`）。消すのは「その日の、変換開始時の最大 rowid 以下の行」であり、確かめた行数と一致しなければ消さない。
- 月ごとの統合、表ごとのロック、バックアップ、書き出し（ZIP の Parquet）。

アーカイブの版（`Archive.SchemaVersion`）は次のとおりである。

| 版 | 内容 |
| --- | --- |
| 1 | 0.21.0 まで |
| 2 | `battery` の追加列、`energy_state` |
| 3 | `fixes` の追加列、`pressure` |

- 列は表の末尾に足すだけで、消さない。
- ファイルは版を持たない。列がファイルの版を表す。生データの新形式（[生データの保存形式](detail-log-format.md) の schema 4）は版を footer に書く予定であり、それとは番号が重ならない。
- 読むときは `Archive.open` が表の今の列に名前と型で合わせ、ファイルにない列を NULL とする。
- 遅れて来た行を既存の日のファイルに併合する場合、ファイルが古い版なら行グループを写さずにデコードして書き直す。今の版のファイルは従来どおり写す。
- 今の版が知らない列を持つファイル（新しい版が書いたもの）は書き直さない。書き直すとその列の値が消えるので、例外で止まる。読むだけなら知っている列を返す。
- `ArchiveSchemaSuite` が、0.21.0 の列で書いたファイルの読み、併合、書き直しの拒否を試験する。

### 開いている区間とアーカイブ

`energy_state` の開いている区間（`end` が NULL）は変換しない（`DbSchema.archivable`）。
閉じたときにその日の変換に加わる。日が既に変換済みなら、遅れて来た行として併合する。

区間を閉じるとき、行を UPDATE せず、開いた行を消して閉じた行を新しい rowid で入れる。
変換は「開始時の最大 rowid 以下の、閉じた行」を消す。
UPDATE で閉じると、変換中に閉じた行（rowid はその最大以下）が、変換されないまま消える。
新しい rowid は床から取るので最大より大きく、消されない。
`DbMigrationSuite` がこの競合を SQL で再現して確かめる。

## プライバシー

- 記録と推定はすべて端末の中で行う。気圧計、電池の値、海抜高度の換算のどれも通信しない。権限も増えない。
- `energy_state` と `pressure` は同期しない（`Archive.UploadedSignalTables` に含めない）。端末の中のアーカイブ、バックアップ、書き出しには含める。
- `fixes` と `battery` の追加列は、従来どおりそれぞれの日のファイルに含まれ、暗号化して同期する。同期サーバの運用者には読めない。追加列の分だけファイルが大きくなり、運用者に見える大きさが変わる。
- `status` の stream は変えない。
- 端末診断の「レポートをコピー」は、推定の結果（%/時、測位の間隔と精度の中央値）を含む。利用者の操作でだけクリップボードに置く。

## 未決事項

1. **同期の範囲。** `energy_state` と `pressure` を同期しないので、端末を失うとこれらは戻らない。気圧は建物の階の上下を測れる精度を持つ。暗号化した `archive` に含めて同期するか、端末に留めるか。
2. **小さい行の退避。** 新しい種類はファイルへ退避しない。SQLite に数日書けない場合、20 万行を超えた分は失う（計上して通知はする）。小さい行にも退避が要るか。
3. **強制終了時の区間。** 開いた区間は、SQLite にある最後の電池の読み（最大 5 分前）で閉じる。その日の `battery` が既に変換済み（ロガーが 1 日以上止まっていた場合）なら、区間の長さは 0 になる。終了時刻の決め方をこれでよいとするか。
4. **気圧の取りこぼし。** プロセスが死ぬと、閉じていない区切り（最大 1 分）と、センサーハブがまだ渡していない読み（最大 60 秒）を失う。測位（最大 5 秒）より長い。
5. **海抜高度の換算の場所。** `AltitudeConverter` はロガーのスレッドで呼ぶ。地域の初回にディスク I/O がある（最初の 1 回の所要時間をログに出す）。端末で測っていない。
6. **アーカイブの版の表し方。** ファイルは版を持たず、列で判断する。列の意味を変える変更（単位や符号）はこの方式では表せない。schema 4 と同じく footer の key-value metadata に版を書くか。
7. **日の削除。** 「この日を削除」は今も SQLite の `fixes` と `motion` だけを消す。`battery`、`energy_state`、`pressure` と、アーカイブ済みの日は残る。
8. **推定の妥当性。** `EnergyModel` の係数と `Elevation.estimate` は合成データでしか試験していない。電流の符号や単位、残量計の有無は端末によって違う。
9. **版を戻せない。** 版 8 のデータベースは 0.21.0 では開けない。バックアップから古い版のアプリに戻す経路があるなら、その扱いを決める必要がある。
