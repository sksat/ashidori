# 自動モード（設計案）

> 状態：**提案**。未実装である。
> 前提となる計測（電池の記録と消費の推定）は実装済みで、その内容を [前提となる計測](#前提となる計測) に記す。

## 目的

利用者が選ぶ記録モード（省電力、バランス、高精度、最高精度）に「自動」を加える。
自動は、1 日に記録へ使ってよい電池の量（予算）の範囲で、記録の細かさを状況に応じて決める。
利用者は予算だけを決め、モードを切り替えなくてよい。

## 予算

- 予算は「記録による消費」の 1 日あたりの上限（電池の %）とする。既定値は 5% 程度とし、設定で変えられる。
- 「記録による消費」は画面オフ・静止中の端末全体の消費を超える分であり、GNSS、生データ記録、移動の検出の合計である。端末全体の画面オフ・静止中と画面オンの消費は含めない。
- 予算の残りは、直近の充電の終わりから数える。

## ペース配分

- 利用者のいつもの充電時刻を、記録した充電の区間から学ぶ（曜日別の中央値など）。
- 次の充電までの残り時間 `T` と予算の残り `B` から、許容する消費率 `B / T`（%/時）を求める。
- 各モードの消費率は、推定した係数と、その時点の状況（動き、屋内外）を方策 `SamplingPolicy` に通した露出から求める。許容する消費率に収まる最も細かいモードを選ぶ。
- 予算を使い切る見込みのときは段階的に下げる。充電の時刻が近いときや予算が余るときは上げる。
- 既存の電池残量による段下げ（30% 以下、15% 以下）と throttle は、自動の判断より優先する。

## 状況の規則

| 状況 | 方針 |
| --- | --- |
| 充電中 | 予算を数えない。高精度で記録する（既存の 1 段上げを含む） |
| よく知る場所で静止 | 静止モードのまま。周期の生データ記録を減らす |
| 知らない場所、または移動中 | 予算の範囲で細かく記録する。移動の始まりは細かく取る |
| 屋内で移動 | 既存どおり省電力測位と短い GNSS の試行 |

「よく知る場所」は、登録した場所と、滞在の多い場所（`Places`）から決める。
規則は方策の入力に加え、純粋関数として `core` に置き、合成データで試験する。

## 前提となる計測

この段階で次を記録している。

- `battery` 表：5 分ごとと状態が変わるたびに、残量（%）、残量計（µAh）、平均と瞬時の電流（放電を正とする µA）、電圧、温度、給電の種類。
- `energy_state` 表：GNSS の要求（有無、間隔、方式）、生データ記録、静止モード、画面、充電、記録モード、動きと屋内外の推定が変わるたびに、開始と終了の時刻で 1 行。

`EnergyModel` は、充電を除く連続した読みの区間ごとの減り（残量計があればその差、なければ % の差）を、各状態の時間の和として非負の最小二乗（Huber の重み）で当てはめ、次を推定する。

- 画面オフ・静止中（端末全体）の %/時
- GNSS の上乗せ（要求間隔の区分ごと）、生データ記録の上乗せ、移動の検出の上乗せの %/時
- 画面オンの %/時（ashidori 以外を含むため、記録には帰さない）

自動モードは加えて次を必要とする。

- 充電の区間（`energy_state` の `charging`）から学ぶ、いつもの充電時刻。
- モードごとの 1 日の消費の推定（`EnergyModel.planExposure` と利用者のいつもの 1 日の動き）。
- 予算の残りを記録の再開後も保つための、前回の充電の終わりと使った量の保存。

## 未決事項

- 予算の既定値と、利用者への見せ方（「1 日 5%」か「残り何時間分」か）。
- 推定が足りない間（数日分の記録がない、ある区分の GNSS を使っていない）の振る舞い。バランスとして動き、推定がそろってから自動に移るのが無難である。
- 端末ごとの差（電流の符号、残量計の有無）。残量計がない端末では % の差しか使えず、推定が粗い。
