# Web の画面

[概要に戻る](overview.md)

Web の画面（閲覧と管理）の設計の規則である。
閲覧は [Web での閲覧](web-viewer.md) にあり、管理は `/admin/` に最小限の実装がある。
見た目は HTML のモックで確かめる。

## 方針

優先順に並べる。

1. 閲覧が主、管理は従。サイトを開くと自分のタイムラインを表示する。
2. 閲覧はアプリと同じ構成、用語、色、操作にする（Nielsen H4 一貫性）。
3. 状態は配置、色、アイコン、凡例で示す。説明文に頼らない。
4. 管理者に位置の記録を見せない。そのことを管理の画面に常に示す。
5. 取り消せない操作は、結果を示して確認してから行う。
6. 色だけで意味を伝えない。全体を一つの色相に寄せない。

## 利用者と目的

| 利用者 | 目的 | 頻度 |
| --- | --- | --- |
| 本人 | 日・週・月の記録を見返す。各端末の最新の状態を見る | 主 |
| 管理者 | 招待の作成とペアリングコードの発行。設定や容量の問題への対応 | 時々 |
| 管理者 | 紛失・不審な端末の失効、共有チェックインの削除 | まれ |

管理者も本人として閲覧を使う。
管理者として位置の記録を読むことはできない。

## 情報設計

```
/          閲覧
├ タイムライン  既定。日・週・月
├ マップ       日・週・月の経路と集計
├ 端末         各端末の状態、このブラウザ
└ ペアリング    未登録のときだけ
/admin/    管理（管理者にだけ入口を表示）
├ 招待         作成（リンクと QR コード）、一覧、取り消し
├ 利用者       先頭に要対応。一覧 → 詳細
│              詳細: コード発行、ユーザ名の設定、端末と失効、共有チェックインと削除、停止
└ サーバ設定    読み取り専用
```

- 閲覧の区分はアプリの下部タブ（タイムライン、マップ、ステータス）に合わせる。Web には記録の機能がないので、ステータスの代わりに端末を置く。
- 広い画面では上部のバー、640 px 未満ではアプリと同じ下部のナビゲーションに置く。
- 「管理」は管理者と確認できたときだけ表示し、区切り線と紫で閲覧と分ける。
- 端末と共有チェックインの一覧を管理の最上位に置かない。どちらもまれな操作なので、利用者の詳細の中で扱う。
- 要対応は件数のダッシュボードにしない。対応の要るものだけを利用者の一覧の先頭に並べ、なければ「問題はありません」と一行で示す。
- 画面を切り替えたら見出しにフォーカスを移し、`<title>` を更新する。

## 閲覧

### タイムライン

- 日・週・月の切り替え、端末の選択、日付への移動、「今日へ」を上に置く。
- 新しい順に過去へ遡る。末尾に近づくと続きを読み込み、同じ位置に「さらに前を表示」のボタンも置く。最古の記録の後は「これより前の記録はありません」。
- 日: 見出し（「今日　10月14日 (水)」と歩数・距離）、その日の地図、滞在と移動の行。行は新しい順で、レールは滞在が青緑、移動が主な移動手段の色。
- 週・月: カードに地図、「44.3 km・14,111歩・4か所・記録 2日」、移動手段の内訳の帯と距離。
- チェックインは滞在の行のチップに出す。フォロワーに共有したものには共有の印を付ける。フォローしている人のチェックインも、対応するときは同じ場所に出す。
- 閲覧専用である。場所の名前や移動手段の修正はアプリで行う。

| 幅 | 配置 |
| --- | --- |
| 960 px 以上 | 左に一覧、右に追従する大きな地図。日、期間、行を選ぶと地図がその範囲を表示し、行の区間を強調する |
| 960 px 未満 | アプリと同じく、日やカードごとに小さな地図を置く。行を選ぶとその地図で強調する |

### 今日の記録

今日の分は同期ごとに届いた間引き済みの区間であり、日が終わると全点のアーカイブに置き換わる。
控えめに示し、帯やバナーは使わない。

- 日の見出しの下に橙の小さな印と「14:05 まで」。フォーカスとホバーで一文の説明を出す。
- 今日の移動の行のレールと、地図の線を破線にする。凡例に「今日（14:05 まで）」を載せる。

### マップ

- 大きな地図と、日・週・月の切り替え、前後の移動、集計（日は歩数・移動・滞在、期間は移動・歩数・場所）、移動手段の内訳を並べる。
- 「この日のタイムライン」でタイムラインの該当の日へ移る。
- 今日の表示では最終測位を精度の円と点で示す。

### 端末

- アプリのステータスの「端末」と同じ行にする。名前、更新からの経過、記録モード（色付きの「● バランス」、止まっていれば「■ 停止中」）、電池、場所と最終測位。
- 更新が 3 時間以上ないときは、経過を赤にして警告のアイコンを添える。
- 選んだ端末の詳細に、地図、更新・記録・電池、位置（場所、座標、測位）、端末（機種、アプリ、受信）を出す。
- 「更新」で最新の状態を取り直す。
- 「このブラウザ」に名前、配信元のドメイン、登録日時、鍵の保存方法、「登録を解除」を置く。

### ペアリング

ブラウザ側は 3 段のステッパにする（手順は [`design/browser-pairing-v1.md`](design/browser-pairing-v1.md)）。
ブラウザがコードを表示し、利用者がアプリに入力する。
アプリの「承認」は鍵を渡す判断、ブラウザの「一致する」は鍵がそのアプリから来たことの確認であり、両方が要る。
ブラウザで照合を省くと、サーバがアプリになりすまして偽の鍵を渡せるためである。

| 段 | 表示 | 期限 | 失敗 |
| --- | --- | --- | --- |
| 1 コードの表示 | 選択の注意（[プライバシーの伝え方](#プライバシーの伝え方)）、「コードを表示」、`XXXX-XXXX` のコードとコピー、アプリでの入力の手順 | 作成から 10 分 | 作成の失敗: その場所に原因と再試行 |
| 2 確認コードの照合 | 番号付きの 4 語、アプリが選んだ期限、「一致する」「一致しない」、承認を待つ表示、残り時間 | 同じ 10 分 | 「一致しない」で中止の画面。期限切れで時間切れの画面 |
| 3 完了 | 鍵の保存方法（このタブを閉じるまで）、「タイムラインを開く」 | — | 受信や開封の失敗はやり直しの画面 |

- 現在の段に `aria-current="step"` を付ける。
- 残り時間は毎秒更新し、読み上げは残り 1 分と 30 秒のときだけにする。
- 中止、期限切れ、失敗のいずれでも一時的な鍵を破棄し、「最初からやり直す」を一つ置く。
- 鍵はメモリだけに置く。共用の PC に鍵を残さないためである。

## 管理

| 画面 | 内容 | 主な操作 |
| --- | --- | --- |
| 招待 | 招待の一覧（未使用、使用済み、期限切れ、取り消し済み） | 招待を作成、取り消す |
| 利用者 | 要対応（設定の不備、使用量 80% 以上の利用者、サーバ全体の上限、旧形式の利用者の「ユーザ名未設定」）、全体の利用者数と保存量、一覧 | ユーザ名を設定 |
| 利用者の詳細 | 状態、使用量、端末、共有チェックイン | ペアリングコードの発行 |
| サーバ設定 | 項目ごとの状態（正常、不正、未設定）、既定値かどうか、不備の影響 | なし |

- 管理者は利用者を作らない。招待を作り、本人が最初の端末でユーザ名を決めて登録する。
- 招待とペアリングコードは、登録リンクとその QR コードで示し、コピー、有効期限、「1 回限り」を添える。ペアリングコードの期限が切れたら値を消し、「再発行」を出す。
- 詳細の末尾に赤枠の区画を設け、「利用者を停止」を置く。
- 設定の不備は全管理画面の上部の帯にも一文で出す。

## 状態の表し方

全画面で同じ形にする（H1 状態の可視化）。

| 状態 | 表示 |
| --- | --- |
| 読み込み中 | 完成形に近いスケルトン。300 ms 未満なら出さない。閲覧は「復号中 3 / 7 日」 |
| 空 | ないものを一文で示し、次の操作を一つ置く |
| エラー | その場所に一文と「再試行」。HTTP の状態は小さく添える |
| 一部未受信 | 表示できる分は出し、該当の日に一行で示す |
| オフライン | 上部の帯に「オフライン」と取得時刻 |
| セッション切れ | 管理: 帯に「再度サインイン」。入力中の内容は保持する。閲覧: 登録が解除されたら鍵を消去し、ペアリングへ導く |

## 操作の規則

| 操作 | 確認 | 取り消し |
| --- | --- | --- |
| 端末の失効 | する | できない |
| 共有チェックインの削除 | する | できない |
| このブラウザの登録の解除 | する | できない |
| 利用者の停止 | する（本人の全端末に及ぶ） | トーストの「元に戻す」で再開 |
| 利用者の再開、ユーザ名の変更 | しない | トーストの「元に戻す」 |
| 招待の取り消し | する | できない |
| 絞り込み、並べ替え、日付の移動 | しない | — |

- 確認はページ内のダイアログで行う。`alert`、`confirm`、`prompt` は使わない（H5 エラーの防止、WCAG 3.3.4）。
  - 題名は対象と動作（「Pixel 7 を失効しますか」）。
  - 本文は結果を 1〜3 行の箇条書き。取り消せないことを明記する。
  - ボタンは「キャンセル」と動作名（「失効する」）。初期フォーカスは「キャンセル」。
- 破壊的な操作は主な操作から離す。詳細画面の末尾の区画か、行の右端に置く。
- 楽観的更新はしない。サーバの応答を正とし、送信中はボタンを「〜中」にして二重送信を防ぐ。
- 成功はトーストに一文（「失効しました」）。6 秒で消え、ホバーとフォーカスの間は止める。トーストの操作は他の場所からも行えるようにする（WCAG 2.2.1）。
- 失敗はトーストでなく、その場所に示す。

## フォームと検証

- ラベルを常に表示する。プレースホルダをラベルの代わりにしない（WCAG 3.3.2）。
- 任意の項目に「任意」と付ける。
- 形式の条件は入力欄の下に常に出す。
- 検証は、一度入力した欄を離れたときと送信時に行う。
- 送信時に誤りがあれば、先頭に誤りの一覧を出してフォーカスし、各欄へ移れるようにする（WCAG 3.3.1、3.3.3）。
- 欄の誤りは `aria-invalid` と `aria-describedby` で結び、アイコンと文で示す。
- サーバの誤り（ユーザ名の重複など）も該当の欄に出す。
- 失敗した送信の入力は消さない（WCAG 3.3.7）。
- クライアントの検証はサーバと同じ規則にする。

| 項目 | 規則 |
| --- | --- |
| 端末名 | 1〜64 文字、制御文字なし |
| ユーザ名 | 必須。英小文字・数字・`_` の 3〜20 文字。大文字は小文字として扱う。本人が最初の端末で決める（旧形式の利用者は管理者が設定する） |
| メールアドレス | 任意。254 文字以内 |
| コード | ハイフン、空白、大小文字の違いを吸収する。貼り付けを許す（WCAG 3.3.8） |

## 表

- 並べ替えは列見出しのボタンで行い、`aria-sort` で示す。
- 絞り込みは検索欄と状態の切り替え（件数付き）。結果の件数を `role="status"` で知らせる。
- 50 件ごとにページを送り、「1–50 / 132 件」と示す。
- 利用者の一覧は行全体で詳細を開く。一覧には破壊的な操作を置かない。
- 640 px 未満では行をカードにし、値に列名を添える。並べ替えは選択欄に移す。
- 数値は等幅の数字にし、右に揃える。

## 時刻

- 相対（「15分前」）を主に示し、絶対（`2026-10-14 14:05 JST`）をホバーとフォーカスで示す。タップでもフォーカスで出る。Esc で閉じる（WCAG 1.4.13）。
- 7 日以上前は日付だけを示す。
- 1 時間単位に丸めた値（管理の最終アクセス）は「1時間以内」「3時間前」と示し、細かく見せない。絶対の表記は「13時台」。
- タイムラインの日付と時刻はアプリと同じ表記（「10月13日 (火)」「19:23 – 21:19」）。
- タイムゾーンはブラウザのものとする。日の区切りは端末の日付に従う。
- 期限は残り時間（`9:58`）で示す。

## 数値と単位

閲覧はアプリの表記に合わせる。

| 量 | 表記 |
| --- | --- |
| 距離 | 1 km 未満は m の整数、以上は km の小数 1 桁。精度の低い区間は「約」 |
| 所要時間 | 「34分」「1時間55分」 |
| 歩数 | 「9,398歩」 |
| 容量 | 2 進の単位（KiB、MiB、GiB）、小数 1 桁 |
| 割合 | 整数に切り捨て。80% 以上は警告、100% で上限 |
| 件数 | 3 桁区切り |
| 電池 | 「78%」。充電中は ⚡ |

## 地図

- 既定は地図の画像のない簡素な表示とする。簡易地図は「簡易地図を読み込む（約 64 MB）」で全体を一度だけ取得し、固定の SHA-256 で確かめてブラウザの中で読む。範囲指定やタイルごとの取得はしない（見ている地域がサーバに伝わるため）。帰属表示に「このサーバから配信」を添える。
- 外部のタイル（「詳しい地図」）は当面置かない。CSP は他のオリジンへの要求を許さず、スクリプトはビューアのファイルのパス（`/assets/`、`/vendor/`）だけに許す。
- 拡大、縮小、全体表示のボタンを置く。ドラッグに加え、地図にフォーカスがある間は矢印キー、`+`、`−`、`0` で操作できる（WCAG 2.1.1、2.5.7）。
- タイムラインの一覧を地図の代わりの手段とする。地図の SVG は読み上げの対象から外す。
- 線の色は移動手段の色（アプリと同じ値）とし、精度の低い区間は淡くする。滞在は点で示す。
- 地図に描く端末は選択中の一台だけにし、色で端末を区別しない。
- 凡例は表示中の要素だけを載せる。凡例は左下、帰属表示は右下に置き、重ねない。狭い画面では凡例を畳む。

## プライバシーの伝え方

ブラウザでの閲覧を選ぶ時点（アプリの切り替えとペアリング）にだけ、次の 2 行を示す。

> **ブラウザでも見る**
> アプリだけで見る場合より、保護は弱くなります。[詳しく]

- 「詳しく」は [Web での閲覧](web-viewer.md) に当たる説明を開く。配信元のドメイン、サーバの管理者の名前、管理者が画面を書き換えると記録を見られる可能性があること、登録はいつでも解除できることを箇条書きで示す。
- 管理者の名前はサーバの設定（`OPERATOR_NAME`、新設）から取る。
- 閲覧の各画面には繰り返さない。「このブラウザ」に配信元のドメインを示すだけにする。

| 場所 | 表示 |
| --- | --- |
| 管理の上部 | 錠前のアイコンと「位置の記録は本人の端末だけが読めます」を常に表示 |
| 閲覧の共有チェックイン | 共有の印。ヘルプに「共有したチェックインは、フォロワーとサーバの管理者が読めます」 |
| 管理の共有チェックイン | 「利用者がフォロワーに共有したチェックインです。共有されたものだけが表示されます（位置の記録は表示されません）」 |
| 地図 | 帰属表示に「このサーバから配信」 |

- 管理の画面に座標、地図、経路を出さない。共有チェックインも施設名と地名だけを出す。
- 紫はサーバの管理者に関わるもの（管理、選択時の注意、ブラウザの端末）に使う。主な操作は青緑、選択中の切り替えは淡い橙（アプリと同じ）、今日の印は橙とする。

## 文言

1. 網羅より簡潔を優先する。通知は短い一文にする。詳細は本当に必要なときだけヘルプに置く。
2. 誰が読めるかで書く。「平文」「暗号化」「E2EE」「公開鍵」「AAD」などを先に出さない。必要ならヘルプの中で補う。
   - 良い例:「共有したチェックインは、フォロワーとサーバの管理者が読めます」
   - 悪い例:「フォロワーに共有されたものだけが平文で保存されています」
3. 選択の注意は結果を一文で述べ、詳細は「詳しく」に回す。「信頼」のような判断を求める抽象語を先に出さない。
4. 実装の詳細や説明の括弧書きを出さない。「管理者（Cloudflare Access）」ではなく「管理者」とする。
5. アプリ名を繰り返さない。上部バーにはサーバのホスト名を出す。
6. 文は「です・ます」、ラベルは正式な語の体言（「最終アクセス」「使用量」）とする。口語を避ける。
7. ボタンは動作名（「失効する」「作成」）とし、「OK」「はい」を使わない。
8. 誤りは原因と次の手順を一文で示し、謝らない。

| 語 | 使い方 |
| --- | --- |
| サーバの管理者 | サーバを運用する者。他の文書の「運用者」に当たる |
| ユーザ名 | 利用者を表す唯一の名前。本人が最初の端末で決め、表示と検索に使う。別の表示名は持たない。「名前」「ハンドル」「ユーザ ID」は使わない |
| 端末 | アプリとブラウザの両方。「デバイス」は使わない |
| 失効 | 管理者が端末の登録を取り消すこと |
| 登録の解除 | 本人がこのブラウザの登録を取り消すこと |
| 停止、再開 | 利用者に対する操作。記録の「■ 停止中」とは記号と場所で区別する |
| 最終アクセス | 端末がサーバに最後に接続した時刻（管理） |
| 更新、測位 | 端末の状態を送った時刻と、最後に位置を得た時刻（閲覧） |
| 滞在、移動、チェックイン | アプリと同じ |

## アクセシビリティ（WCAG 2.2 AA）

| 項目 | 規則 | 達成基準 |
| --- | --- | --- |
| コントラスト | 文字 4.5:1 以上。UI の境界と地図の線 3:1 以上。両テーマで確かめる | 1.4.3、1.4.11 |
| 色だけに頼らない | 状態はピルの語、使用量は数値と警告のアイコン、今日は破線と印、古い状態は赤とアイコン | 1.4.1 |

## ダークモード

- 色はすべて `:root` のトークンで定義し、`prefers-color-scheme` と明示の切り替えの両方で上書きする。
- 暗色では彩度を下げ、明るい色調に替える。主要色の面に載る文字色もトークンで替える。
- 地図の地、道路、水域もトークンにする。移動手段の色はアプリと同じく両テーマで共通とし、線の下に地の色の縁を敷いて 3:1 を保つ。

## 日本語の組版

- 書体は Noto Sans JP、コードには Roboto Mono を使う。数字は `tabular-nums`。
- 本文は 14 px、行間 1.7。見出しは `text-wrap: balance`。
- `line-break: strict` で禁則を守る。メールアドレスなどの長い英数字は `overflow-wrap: anywhere`。
- 斜体を使わない。強調は太字にする。

## セキュリティに関わる UX

- 管理の上部バーに Access の ID（メールアドレス）と「サインアウト」（`/cdn-cgi/access/logout`）を置く。
- 変更の操作は同一オリジンの JSON の要求だけで行う。CSP の `form-action 'none'` でフォームの直接送信を禁じる（CSRF の対策）。
- URL にペアリングコード、鍵、トークンを入れない。
- ペアリングコードは期限が切れたら画面から消す。コピーはボタンで行う。
- 閲覧の鍵（バッチ鍵だけ）は取り出せない `CryptoKey` としてメモリに置く。管理と閲覧は同じオリジンなので、管理の画面に混入したスクリプトにも鍵の値を読ませないためである。
- 利用者の入力（ユーザ名、端末名、コメント）は `textContent` で表示する。
- 閲覧で登録が解除されたら、鍵と復号した内容を直ちに破棄する。
