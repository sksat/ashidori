# 外部への送信の設定とオフラインの地域データ（設計案）

> 状態：**提案**。未実装である。
> 利用者の判断を待つ点を [未決の事項](#9-未決の事項) に挙げる。
> データモデルとプライバシーに関わるため、実装の前に外部のレビューを受ける。
> 外部のサービスについて確かめていない事項は「未確認」と書く。
> 現行の仕様は [`privacy.md`](../privacy.md) と [README の「地名と位置情報の送信」](../../README.md#地名と位置情報の送信) にある。

本書は二つの機能を扱う。

1. **送信先ごとの外部送信の設定**：送信先ごとに、送るかどうか、いつ送るか、どの精度まで送るかを利用者が決める。
2. **オフラインの地域データ**：地域を選び、詳細な地図と施設データを事前に端末へ取得する。

二つは互いに関わる。
地域データがあればオンライン地図に頼らずに済み、地域データの取得自体も外部への送信の一つになる。

## 1. 課題と目標

### 課題

- 外部への送信を制御する設定は「オンライン地図と地名検索」のスイッチ一つ（保存値 `blockExternalLocation`）だけである。
- 実際の送信先は複数あり、送る情報も精度も異なる。地図の配信元には表示範囲を、Android の Geocoder には滞在地の座標を、Overpass には検索した位置を送る。
- 利用者には「この送信先にこの精度なら送ってよいが、あの送信先には送らない」という判断がありうる。一つのスイッチではこれを表せない。
- オフライン地図は日本でズーム 10、全世界でズーム 5 までである。通信できない場所（山、海外の旅行先）で詳細な地図を見る手段がない。

### 目標

1. 送信先ごとに、送信の可否、時機（操作時のみ、自動）、精度を選べる。
2. 既定の動作と、既存の利用者の動作を変えない。
3. 設定の結果を ✓ ／ ⊖ の一覧で示し、説明の段落を置かない。
4. 地域を選んで、詳細な地図と施設データを事前に取得できる。取得で何が誰に伝わるかが画面で分かる。
5. 地域データの取得と更新が記録を妨げない（記録の領域を残し、記録の処理と独立に動く）。

### 対象外

- OS の測位サービスが送る情報（fused と network provider、Google 位置情報の精度）。一覧には参照の行だけを置く（[未決 5](#9-未決の事項)）。
- Web ビューア（ブラウザ）の地図。ブラウザの設定はブラウザに保存する別の仕組みである（[`web-viewer.md`](../web-viewer.md)）。
- 同期プロトコルの変更。

### 2.3 一覧から分かること

- Geocoder には、自分の滞在地だけでなく、同期した他の端末の現在地も送りうる（`PeerStatus.scala:321`）。
- Overpass の予備のインスタンスは、1 回の検索の送信先を最大 4 者に広げる。
- 静止画（フィード、期間のカード、他の端末）は、設定がオンの間、過去の日の範囲を地図の配信元へ自動で送る。表示中の地図より伝わる範囲が広い。
- T1〜T3 の静止画と地図は一つの選択（`mapStyle`）を共有し、送信先は選んだ地図で決まる。

## 3. 設定とデータのモデル

### 3.1 送信先と選べる値

設定は送信先（`Dest`）ごとの規則（`Rule`）の集まりとする。
規則は時機（`When`）と精度（`Level`）の組である。

| `Dest` | 画面の名前 | 選べる時機 | 選べる精度 |
| --- | --- | --- | --- |
| `ofm` | オンライン地図（OpenFreeMap） | 送信しない、操作時のみ、自動 | 地域、地区、制限なし |
| `gsi` | オンライン地図（地理院タイル） | 同上 | 同上 |
| `custom` | オンライン地図（カスタム） | 同上 | 同上 |
| `geocoder` | 地名検索（Android） | 送信しない、自動 | 地域、地区、正確 |
| `overpass` | 施設のオンライン検索 | 送信しない、操作時のみ | 地区、正確 |
| `data` | 地図・施設データの取得 | 送信しない、操作時のみ、自動 | 全域のみ、区画 |

時機の意味は次のとおりである。

- **送信しない**：その送信先には、操作があっても送らない。入口（ボタン、地図の種類）を無効にする。
- **操作時のみ**：利用者がその表示やその検索を指示したときだけ送る。地図では今の「オンライン地図で表示（表示範囲を送信）」と、地図ごとに記憶する同意に当たる。
- **自動**：表示や記録に合わせて送る。地図では静止画とサムネイルも含む。

Geocoder には操作の入口がないので「操作時のみ」を置かない。
Overpass には自動の検索を設けない（今の方針を保つ）。

### 3.2 精度の意味

精度は、送信先から見て位置がどの大きさの範囲に絞られるかで決める。
大きさは格子の 1 辺であり、利用者の位置の誤差ではない。

| 精度 | 地図のタイル（T1〜T3） | 地名検索 | 施設の検索 |
| --- | --- | --- | --- |
| 地域（約 10 km） | ズーム 12 まで取得し、それより拡大した表示はズーム 12 のタイルを引き伸ばす | 0.1° の格子の中心で問い合わせ、市区町村と国だけを使う | 選べない |
| 地区（約 1 km） | ズーム 15 まで | 0.01° の格子の中心で問い合わせる | 0.01° の区画とその周囲 8 区画（約 3 km 四方）をまとめて検索し、端末内で近い順に絞り込む |
| 制限なし、正確 | 配信元の最大ズームまで | 座標のまま | 位置と半径のまま |

- タイルの 1 辺は `40075 km × cos(緯度) / 2^z` であり、北緯 35° でズーム 12 は約 8 km、ズーム 15 は約 1 km である。
- 表示範囲は複数のタイルにまたがるため、伝わる範囲はタイルの和集合になる。精度はその粒度を決める。
- 格子はランダムなずらしではなく固定の格子とする。同じ区画からの問い合わせは毎回同じ内容になり、回数を重ねても区画の内側の位置は絞り込めない。区画の境界をまたいだことは伝わる（[7 章](#7-脅威とプライバシーの分析)）。
- OpenFreeMap のベクタタイルは最大ズーム 14 で、それより拡大した表示は 14 のタイルを引き伸ばすと理解している（未確認）。その場合、OpenFreeMap の「地区」と「制限なし」は同じ要求になる。
- 地名検索の「地域」は「…付近」の地名を出さない。0.1° ずらした点の町名は誤りになりうるためである。

「データの取得」の精度は次のとおりである。

| 精度 | 意味 |
| --- | --- |
| 全域のみ | 日本と全世界のオフライン地図、日本の施設データのように、範囲を含まない archive だけを取得する。地域データは取得しない |
| 区画 | 加えて、利用者が選んだ地域の区画（[6.4 節](#64-区画)、約 130 km 四方）を取得する |

### 3.3 型

`core` に置く。

```scala
enum Dest(val key: String):
  case Ofm extends Dest("ofm")
  case Gsi extends Dest("gsi")
  case CustomTiles extends Dest("custom")
  case Geocoder extends Dest("geocoder")
  case Overpass extends Dest("overpass")
  case Data extends Dest("data")

enum When:
  case Never, OnAction, Auto

/** 送信先ごとに意味が異なる。Whole と Cell は Data だけが使う。 */
enum Level:
  case Area, District, Exact, Whole, Cell

/** off: Overpass で使わないインスタンスのホスト。 */
final case class Rule(when: When, level: Level, off: Set[String] = Set.empty)

final case class Policy(rules: Map[Dest, Rule]):
  def rule(d: Dest): Rule
```

`Policy` は、送信先ごとに選べない組（Geocoder の `OnAction` など）を持たない。
読み込みで選べない組を見つけたら、その送信先を `Never` にする。

### 3.4 保存するキー

既存の `settings` の SharedPreferences に置く。

| キー | 型 | 既定 | 内容 |
| --- | --- | --- | --- |
| `externalPolicy` | String（JSON） | なし（なければ移行する） | 送信先ごとの規則 |
| `mapConsents` | String（JSON） | 既存 | 形式は変えない。同意は、その地図の送信先が「操作時のみ」の間だけ有効 |
| `blockExternalLocation` | Boolean | 既存 | 移行の元。移行後は読まず、派生値を書く |
| `externalPaused` | Boolean | false | 「すべて停止」（[未決 3](#9-未決の事項)を採る場合） |
| `regionsAutoUpdate` | Boolean | true | 地域データの自動更新 |
| `regionsMetered` | Boolean | false | 地域データをモバイルデータ通信でも取得するか |

`externalPolicy` は `MapConsents` と同じく、版付きの一つの JSON とする。

```json
{"v":1,"rules":[
  {"dest":"custom","when":"action","level":"exact"},
  {"dest":"data","when":"auto","level":"cell"},
  {"dest":"geocoder","when":"never","level":"exact"},
  {"dest":"gsi","when":"action","level":"exact"},
  {"dest":"ofm","when":"action","level":"exact"},
  {"dest":"overpass","when":"action","level":"exact","off":[]}
]}
```

- 規則と同意は一度の `SharedPreferences.Editor` で書く（今の `persist` と同じ）。
- 読み込みは `MapConsents.load` と同じく正準形だけを受け付ける。読み戻した値を書き直して同じ文字列にならないもの（キーの重複、送信先の重複、余分な項目）は壊れているとみなす。
- 壊れている、または未知の版の場合は、今の既定（[3.5 節](#35-既定値と移行)の左列）とし、同意をすべて捨てる。今の `MapConsents.load` が壊れた値を「設定オン、同意なし」と読むのと同じであり、利用者の操作なしには位置を送らない。`blockExternalLocation` の派生値はこの場合に読まない。
- 未知の送信先の項目は捨てる。足りない送信先は既定の規則で補う。

`blockExternalLocation` の派生値は、規則がすべて旧設定のオフ（[3.5 節](#35-既定値と移行)の右列）と一致するときだけ false、ほかは true とする。
旧版のアプリでこの値を読んでも、新しい設定より多くは送らない。

### 3.5 既定値と移行

起動時の `Settings.migrate()` で、`externalPolicy` がなければ `blockExternalLocation` から作る。
`onlineVenues` の移行（今のコード）を先に行う。

| 送信先 | `blockExternalLocation` が true、または値がない（今の既定） | false |
| --- | --- | --- |
| `ofm`、`gsi`、`custom` | 操作時のみ、制限なし | 自動、制限なし |
| `geocoder` | 送信しない | 自動、正確 |
| `overpass` | 操作時のみ、正確、全インスタンス | 同左 |
| `data` | 自動、区画 | 同左 |

- 新規の利用者は左列になる。今の既定と同じである。
- `mapConsents` は形式を変えずに引き継ぐ。左列では地図の送信先が「操作時のみ」なので、記憶した同意はそのまま有効である。
- この 2 列について、新しい判定の関数が今の関数（`BaseMapPolicy`、`GeocodePolicy`）と同じ結果を返すことを、入力の全組み合わせで試験する（[8 章](#8-試験の計画)）。これを「動作を変えない」の根拠とする。
- `data` の「区画」は地域データの機能とともに入る。地域データの取得は操作でだけ始まるため、移行の時点で新たな送信は起きない。

## 4. SendGate の変更

### 4.1 状態

| 状態 | 今 | 変更後 |
| --- | --- | --- |
| 設定 | `blocked: Boolean` | `policy: Policy` |
| 世代 | 全体で一つの `gen` | 送信先ごとの `gens: Map[Dest, Long]` |
| 票（ticket） | `Long` | 送信先ごとの世代の写し（`Ticket(gens)`） |
| 許可（grant） | 表示 → 世代 | 表示 → （送信先、その世代） |
| 同意 | 地図の画面 → 地図 | 変えない |

送信先ごとに世代を分けるのは、Geocoder の設定を変えたときに、表示中のオンライン地図の許可や待機中の静止画まで取り消さないためである。

### 4.2 API

```scala
final class SendGate(initial: Policy, initialConsents: Map[String, String],
                     persist: (Policy, Map[String, String]) => Unit,
                     destOfMap: String => Option[Dest]):
  def policy: Policy
  def rule(d: Dest): Rule
  /** 規則を変える。変わった場合は d の世代を進め、d の許可と、d の地図への同意を消し、
    * 保存し、listener に d を伝える。 */
  def setRule(d: Dest, r: Rule): Boolean
  def onChange(f: Set[Dest] => Unit): () => Unit

  def ticket(): Ticket
  /** 自動の処理が d へ送ってよいか：d が Auto で、票が d の現在の世代。 */
  def automatic(t: Ticket, d: Dest): Boolean
  /** 票を取った後に d の規則が変わっていない。 */
  def current(t: Ticket, d: Dest): Boolean
  /** 操作による送信を受け付けるか：d が Never でない。 */
  def explicit(d: Dest): Boolean

  def remember(surface: String, map: String): Unit  // 地図の送信先が OnAction の場合だけ記憶する
  def forget(surface: String): Unit
  def consent(surface: String): Option[String]      // 送信先が OnAction の間だけ返す
  def grant(owner: AnyRef, d: Dest): Unit
  def revoke(owner: AnyRef): Unit
  def online(owner: AnyRef, d: Dest): Boolean       // d が Auto、または owner が d の現在の許可を持つ
  def networkAllowed: Boolean                       // タイルの送信先のどれかが Auto、または現在の許可がある
```

- `block`、`setBlock`、`switchOn`、`blockFor` は移行の間だけ残し、呼び出し元を移した後に消す。
- 「すべて停止」を採る場合、`paused` の間はすべての送信先を `Never` として判定する。規則そのものは書き換えない。
- 規則の変更は、精度だけの変更でも許可と同意を消す。同意はその時点の精度で与えられたものであり、精度を上げた後に古い同意で送らないためである。

### 4.3 判定の関数

`BaseMapPolicy` の引数を `block: Boolean` から、選んだ地図の送信先の規則に変える。

| 関数 | 今 | 変更後 |
| --- | --- | --- |
| `interactive` | `block` が false なら選んだ地図、true なら同意した地図 | 選んだ地図の送信先が Auto なら選んだ地図、OnAction なら同意した地図、Never ならオフライン地図 |
| `snapshot` | `block` が false なら選んだ地図 | 選んだ地図の送信先が Auto なら選んだ地図、ほかはオフライン地図 |
| `thumbnail` | `block` が false なら描画 | 送信先が Auto なら描画 |
| `offerAlternatives` | `block` かつ地図なし | 「オンライン地図で表示」の地図の送信先が OnAction かつ地図なし |

精度は次の関数で適用する。

- `Precision.snap(lat, lon, gridDeg): (Double, Double)`：固定の格子の区画の中心を返す。Geocoder と Overpass の「地区」「地域」で使う。
- `Precision.maxZoom(level): Option[Int]`：地域は 12、地区は 15、制限なしは None。

### 4.5 三つの防御線

送信を止める手段を三段に重ねる。

1. **判定**：判定の関数が、送ってはいけない場合に端末内のスタイルを選び、要求そのものを作らない。今と同じく、これが主である。
2. **MapLibre の通信可否**：`MapLibre.setConnected` をプロセス全体に効かせる。今と同じく補助である。
3. **送信の直前の確認（新規）**：アプリが自分で通信する箇所（Overpass、データの取得、Geocoder）は一つの関数 `Outbound.open(dest, url)` を通し、その中で規則と世代を確かめる。MapLibre の通信は、MapLibre の HTTP クライアントを差し替える API（`HttpRequestUtil.setOkHttpClient` と理解している。13.6.1 での有無は未確認）で interceptor を挟み、ホストから送信先を引いて、Never の送信先と、どの地図も通信を許されていない間の要求を拒む。

三段目は、どの表示の要求かを区別できない。
このため、表示ごとの同意の検査は一段目に残る。

### 4.6 形式検証

[`formal/README.md`](../../formal/README.md) が将来の課題に挙げる `SendGate` の TLA+ モデルを、送信先ごとの世代で作る。
送信先 2 つ（タイル 2 種）と Geocoder 1 つ、表示 2 つ、静止画の待ち行列で、次を検査する。

- 自動の処理が送信先 d へ送るのは、d が Auto で、票が d の現在の世代の場合だけ。
- 表示が送信先 d へ送るのは、d が Auto か、その表示が d の現在の許可を持つ場合だけ（別の表示の許可で送らない）。
- Never の送信先へは、操作による送信も含めて送らない。
- 送信先 d の規則の変更は、d と異なる送信先の許可と票を無効にしない（取り消しすぎない）。

## 5. 画面の流れ

### 5.1 設定の入口

設定の「プライバシー」のスイッチ「オンライン地図と地名検索」を、行「データの扱い」に置き換える。
行の補足は送信する送信先の数とする（例「外部への送信 2 件」、すべて送信しない場合は「外部への送信なし」）。

### 5.2 「データの扱い」

画面案の画面 5 に合わせる。
設定の結果を ✓ ／ ⊖ の一覧で示し、段落の説明は置かない。

```
← データの扱い

保存先
  ✓ この端末                       812 MB
  ✓ 同期サーバ                     暗号化して送信 · 最終 5分前   ›

外部への送信
  ✓ オンライン地図（OpenFreeMap）   表示範囲 · 操作時のみ          ›
  ✓ オンライン地図（地理院タイル）  表示範囲 · 操作時のみ          ›
  ⊖ オンライン地図（カスタム）      未設定                        ›
  ⊖ 地名検索                        送信しない                    ›
  ✓ 施設のオンライン検索            位置 · 操作時のみ              ›
  ✓ 地図・施設データの取得          選んだ区画 · GitHub            ›
    位置の取得                      OS の設定による               ›
```

- 記号の形で状態を示す。✓ は送信する、⊖ は送信しない。送信する行の記号は、今の送信の操作と同じ tertiary の色にする。色だけに頼らない。
- 2 行目は「何を · いつ」とし、精度が制限なしでない場合は精度を付ける（例「表示範囲（約 1 km）· 自動」）。
- 「位置の取得」は OS の測位の参照であり、アプリが送信を制御しないので記号を付けない。[未決 5](#9-未決の事項) の結論まで表示だけにする。
- 「すべて停止」を採る場合は、「外部への送信」の見出しの右にスイッチを置く。

### 5.3 送信先の詳細

行を押すと、その送信先の画面を開く。
選択肢は 2 群のラジオボタンと、送信先のホストの 1 行だけとする。

```
← オンライン地図（地理院タイル）

送信
  ○ 送信しない
  ● 操作時のみ
  ○ 自動

精度
  ○ 地域 約 10 km      [格子の凡例]
  ○ 地区 約 1 km       [格子の凡例]
  ● 制限なし           [格子の凡例]

送信先  cyberjapandata.gsi.go.jp
```

- 精度の凡例は、地図の上の格子と、送信先に伝わる区画の塗りで示す（画面案の凡例と同じ）。
- 時機が「送信しない」の間は、精度の群を無効にする。
- 施設のオンライン検索は、精度の下に「検索先」としてインスタンスごとのスイッチを置く。すべてオフは選べない（その場合は「送信しない」を選ぶ）。
- カスタムは「送信先」の行に URL のホストを出し、押すと今の URL の入力を開く。
- 変更は即時に保存し、待機中と実行中の処理はその時点で新しい規則に従う（4.2 節）。

### 5.4 ほかの画面への影響

## 6. オフラインの地域データ

### 6.1 現状

| 項目 | オフライン地図 | 施設データ |
| --- | --- | --- |
| 内容 | 日本（ズーム 6〜10、`japan.pmtiles`）と全世界（ズーム 0〜5、`world.pmtiles`）、スタイル、フォント、スプライト | 日本の施設 1,073,493 件（`venues.aven`） |
| 大きさ | 約 64 MB（archive 63,591,472 バイト） | 約 18 MB |
| 作り方 | `tools/basemap/build.sh`：Protomaps の日次ビルド（`https://build.protomaps.com/<日付>.pmtiles`）から go-pmtiles の `extract` で切り出す | `tools/venues/build.sh`：Geofabrik の日本の抽出から pyosmium で抜き出す |
| 配布 | GitHub Releases（タグ `basemap-<版>`）、同期サーバ（R2） | GitHub Releases（タグ `venues-<版>`） |
| 完全性 | APK に固定した大きさと sha256（`basemap-pin.json`） | 同じ（`venues-pin.json`） |
| 端末 | `filesDir/basemap/<版>/`（`BasemapStore`）、`PinnedDownload` が Range で再開する | `filesDir/venues/<版>/` |

スタイルは二つのソースを重ね、日本を全世界の上に、文字をすべての図形の上に置く（`tools/basemap/assemble.py` の `layers`）。
MapLibre は `pmtiles://file://` のソースを端末内で読んでおり、PMTiles の読み込みはこのアプリで動作を確かめた形式である。

### 6.2 要件

- 地図の上の固定の枠に地図を動かして範囲を合わせ、大きさの見積もりを 1 行で示す（画面案の画面 6）。
- 取得済みの一覧に、名前、大きさ、取得日、︙（更新、名前を変更、削除）、新しい版の印を示す。期限は設けない（画面案の画面 7）。
- 取得したデータは改ざんを検出できる（sha256）。
- 取得は中断しても再開できる。既定では従量制でない回線を待つ。
- 地域データの取得で伝わる情報を、取得の前に画面で示す。
- 取得と展開が記録の領域を使い切らない。

### 6.3 方式の比較

| 方式 | 配信元に伝わる範囲 | 端末の負担 | 完全性 | 配信元の負担 | 評価 |
| --- | --- | --- | --- | --- | --- |
| A. 固定の区画ごとのパックを静的ファイルで配る | 選んだ枠を含む区画の集合（約 130 km 四方の単位） | 区画が枠より広い分だけ大きい。展開なし | ファイルごとの sha256 | 静的ファイルのみ | **採る** |
| B. 大きな archive（日本全体の詳細）を取得し、端末で使う | なし（全体を取得した事実のみ） | 未計測。数 GB と見込むが根拠はない。端末で切り出すなら一時的に 2 倍の容量 | archive の sha256 | 大きなファイル 1 つ | 計測の後に、A に加える選択肢として決める（[未決 8](#9-未決の事項)） |
| C. 端末から大きな PMTiles へ Range 要求を送り、枠の分だけ切り出す（`pmtiles extract` を端末で行う） | 枠そのもの。要求するバイト範囲がタイルの番号に対応するため、配信元は範囲を復元できる | 要求の数が多い | 切り出した部分は archive の sha256 で照合できない。タイルごとの署名つき一覧が別に要る | 細かい Range 要求が多数 | 採らない |
| D. MapLibre の機能でオンライン地図の配信元からタイルを一括取得する | 枠そのもの（タイル単位） | タイル数が多い（ラスタ） | なし | 配信元にタイルの一括取得を課す。各配信元の利用条件は確かめていない | 採らない |

A を採る理由は次のとおりである。

- 伝わる範囲が区画の単位に粗くなり、枠の位置そのものは伝わらない。
- 今の配布の仕組み（静的ファイル、大きさと sha256 の固定、Range での再開、`BasemapStore` の原子的な配置）をそのまま使える。
- 区画は複数の地域で共有でき、重複して取得しない。

### 6.4 区画

区画は、Web メルカトルのズーム 8 のタイルとする（識別子 `8-<x>-<y>`）。

- 1 辺は北緯 35° で約 128 km である。
- PMTiles のタイルの番号と揃うので、区画の内側のタイルはズーム 8 以上で区画の外にはみ出さない。隣の区画とタイルが重ならない。
- `tools/basemap/japan.geojson`（長方形の集まり）と交わるズーム 8 の区画は 136 個である（海だけの区画を含む。本書の作成時に数えた）。
- パックはズーム 8〜15 の、その区画の内側のタイルを持つ。タイル数は最大 21,845 である。
- Protomaps のビルドの最大ズームは 15 と理解している。ビルドの metadata で確かめる。
- パックの大きさは計測していない。都市部と山間部で大きく異なると見込む。区画ごとの大きさは、最初の作業として日本の全区画で測る。

### 6.5 パックとカタログ

| ファイル | 内容 |
| --- | --- |
| `ashidori-region-8-<x>-<y>-<版>.pmtiles` | 区画の地図（PMTiles v3、ズーム 8〜15）。zip に包まない |
| `ashidori-venues-8-<x>-<y>-<版>.aven` | 区画の施設データ（日本の外の区画だけ。[6.13 節](#613-施設データ)） |
| `ashidori-regions-<版>.json` | カタログ：区画ごとのファイル名、大きさ、sha256、範囲、ズーム、ビルドの日付、施設の件数 |

カタログの例を示す。

```json
{"format":"ashidori regions catalog v1","version":"20261201","build":"20261201",
 "minzoom":8,"maxzoom":15,
 "cells":[
  {"cell":"8-227-100","map":{"file":"ashidori-region-8-227-100-20261201.pmtiles","bytes":123456789,"sha256":"…"},
   "venues":null}
 ]}
```

完全性は二段で確かめる。

1. APK はカタログの大きさと sha256 を固定する（`regions-pin.json`、今の `BasemapPin` と同じ形式）。カタログの取得は位置を含まない。
2. パックはカタログの大きさと sha256 で照合する。照合の後に PMTiles のヘッダを読み、範囲が区画の内側に、ズームがカタログの値に収まることも確かめる。

この形では、データの更新はアプリの版の更新とともに届く（今のオフライン地図と同じ）。
アプリと独立にデータを更新するための署名つきのカタログは、[未決 6](#9-未決の事項) とする。

配布は GitHub Releases のタグ `regions-<版>` とする。
GitHub のリリースには 1 ファイルの大きさとファイル数の上限がある。1 ファイル 2 GiB 未満と理解しているが、ファイル数の上限とともに GitHub の文書で確かめる。
日本の区画だけなら、地図のパックは 136 個以下である。

### 6.6 地域とパックの関係

利用者が名前を付けて管理する単位を **地域**、取得の単位を **パック** とする。

- 地域は名前と区画の集合を持つ。枠で選んだ範囲が複数の区画にかかれば、その地域は複数のパックを参照する。
- パックは参照する地域の数を持ち、0 になったら削除する。
- 地域の大きさは、その地域が参照するパックの合計とする。他の地域と共有するパックも含める。
- 地域の名前の既定値は、枠の中心の地名を端末内の索引で求めたもの（例「つくば市周辺」）とする。索引で求まらない場合は「地域 1」のように番号を付ける。Geocoder は使わない。

### 6.7 保存

```
filesDir/regions/
  state.json                      地域、パック、版、取得日、参照数
  packs/<cell>/<版>/map.pmtiles   完全なパック（ディレクトリの改名で現れる）
  packs/<cell>/<版>/venues.aven
  .download/<file>.part           取得中のファイル
```

- 状態は記録のデータベースに入れず、`state.json` に一時ファイルと改名で書く。地域データの処理が記録のデータベースの書き込みと競合しないためである。
- パックは `BasemapStore` と同じく、検証の後にディレクトリを改名して置く。ディレクトリがあれば完全である。
- 更新では、新しい版の検証と配置が済むまで古い版を残す。通信できない場所で更新が失敗しても地図は消えない。
- 取得を始める前に、残りの大きさと 16 MB に加えて、記録の領域として 256 MB（`Backup.LoggingMargin` と同じ値）が残ることを確かめる。取得中も 64 KiB ごとの書き込みで空きを確かめ、下回れば中断する。

### 6.8 取得

- WorkManager の一意の作業（`regions-download`）が、待ち行列のパックを 1 つずつ取得する。今の `PinnedWorker` と同じく、`ResumableDownload`（Range での再開）と `DownloadRetry` を使う。
- 既定では従量制でない回線を待つ（`regionsMetered` が false）。モバイルデータ通信の場合は、今のオフライン地図と同じ確認の画面を出す。
- 取得の要求は端末のトークンもクッキーも持たない。User-Agent は今と同じ `ashidori/<版>` とする。
- 取得の順序はカタログの順ではなく、選んだ順とする。

### 6.9 地図への組み込み

端末内のスタイルは、今のスタイルに取得済みのパックのソースを加えて作る。

- パックごとにソース `r-8-<x>-<y>`（`pmtiles://file://…/map.pmtiles`、`minzoom` 8、`maxzoom` 15、`bounds` は区画）を加える。
- 層は、オフライン地図と同じ Protomaps の層の定義を、パックのソースの名前で複製する。順序は「全世界の図形、日本の図形、パックの図形、全世界の文字、日本の文字、パックの文字」とし、今の `assemble.py` の重ね方に従う。
- パックの層の定義は、オフライン地図の archive に雛形（ソースの名前を置き換える層の一覧）として加える。そのため、オフライン地図のツールの変更と archive の新しい版が要る。
- 区画の内側では、パックの図形がオフライン地図の図形を覆う。文字の重なりは MapLibre の衝突の判定に任せる。区画の境界と、ズーム 8〜10 で日本のソースと重なる部分の見た目は実機で確かめる。
- フォントは、パックの文字列に含まれる文字の範囲も含める。漢字とかなは端末のフォントで描くが、それ以外の範囲がオフライン地図の archive にない場合、その文字は描かれない（`assemble.py` は使わない範囲を空のファイルにする）。
- ソースの数が増えると描画の負担が増える。パックの数の上限（例 16）を設け、実機で測ってから決める。上限を超える使い方が要る場合は、端末で複数のパックを一つの PMTiles に合成する方式を検討する（[未決 11](#9-未決の事項)）。
- パックの追加と削除でスタイルを作り直し、表示中の地図に読み込み直させる。スタイルの照合（`OfflineBasemapStyle.remoteUrls` が空）は今と同じく行う。

### 6.10 範囲の選択

画面案の画面 6 に合わせる。

```
✕  この範囲の地図を取得

   ┌──────────────┐   区画の枠（薄い線）を地図に重ねる
   │   固定の枠   │
   └──────────────┘

   180 MB · 空き 41.2 GB
   GitHub に伝わる範囲: 区画 2 個

   [キャンセル]          [ダウンロード]
```

- 枠は画面に固定し、利用者は地図を動かし拡大縮小して範囲を合わせる。
- 枠と交わる区画を地図に薄い線で示す。取得するのは枠ではなく区画であり、その区画が配信元に伝わる。
- 大きさはカタログの値の合計であり、見積もりではない。取得済みの区画は除く。
- 区画が上限（例 4 個）を超える縮尺では、「範囲を狭めてください」と出し、ダウンロードを無効にする。
- カタログにない区画（日本の外など）は灰色にし、合計に含めない。
- 入口は、地図のタブの ︙ の「地図をダウンロード」と、「オフラインのデータ」の「＋ 範囲を選んで取得」とする。

### 6.11 管理の一覧

画面案の画面 7 に合わせ、「オフラインのデータ」とする。
今の「オフライン地図」と「施設データ」の行も、同じ部品でこの一覧に入れる。

```
← オフラインのデータ                     ＋ 範囲を選んで取得

  ✓ 関東                新しい版     412 MB · 2026/10/13   ⋮
  ✓ つくば周辺                        38 MB · 2026/11/02   ⋮
  ↓ 香港                              取得中 · 38%          ⋮
  ✓ オフライン地図 · 全域             64 MB · 2026/10/13   ⋮
  ✓ 施設データ · 日本                 18 MB · 2026/10/14   ⋮
```

- 状態は先頭の記号で示す（✓ 取得済み、↓ 取得中・待機中、! 失敗）。失敗は error の色の 2 行目に理由を出す。
- 取得日は、その地域のパックを最後に取得した日とする。
- 「新しい版」の印は、地域のパックのどれかについて、APK のカタログの版が端末の版より新しい場合に出す。
- ︙ は「更新」「名前を変更」「削除」とする。「更新」は新しい版がある場合だけ有効にする。「削除」は、他の地域と共有しないパックだけを消すことを確認の画面の 1 行で示す。
- 期限は設けない。古い版も削除されるまで使える。

### 6.12 更新と設定

| 設定 | 既定 | 内容 |
| --- | --- | --- |
| 自動更新 | オン（Wi-Fi 接続時） | 新しいカタログを持つアプリに更新された後、取得済みの区画の新しい版を、従量制でない回線で取得する |
| モバイルデータ通信でも取得 | オフ | オンにすると、操作による取得と自動更新が従量制の回線でも動く |

- 自動更新は `data` の時機が「自動」の場合だけ動く。「操作時のみ」では、一覧の「更新」でだけ更新する。
- 自動更新は同じ区画を再び要求するので、配信元にはその区画への関心が続いていることが伝わる（[7 章](#7-脅威とプライバシーの分析)）。

### 6.13 施設データ

- 日本は今の施設データ（日本全体で約 18 MB）をそのまま使う。区画に分けても伝わる範囲が粗くなるだけで、大きさの利点が小さいためである。
- 日本の外の区画は、地図と同じ区画で施設データのパックを作る。地域を取得すると、地図と施設のパックを合わせて取得する。
- `VenueData` は今は索引を一つだけ開く。区画の索引を複数開き、検索の位置に交わる索引だけを引くように変える。`VenueIndex` の AVEN 形式は格子の原点と大きさを持つので、形式は変えずに区画ごとに作れる。
- 施設の名前での検索（`VenueData.search`）は、取得済みのすべての索引を引き、距離で並べる。

### 6.14 外部送信の設定との関係

- 地域データの取得は、`data` が「区画」で「送信しない」でない場合だけ使える。「全域のみ」では「＋ 範囲を選んで取得」を出さない。
- 範囲の選択とダウンロードの操作を、区画を送る同意とする。取得の画面に「GitHub に伝わる範囲: 区画 N 個」を出す。
- 同期サーバからは地域データを取得しない。運用者に区画が伝わる点では GitHub と同じであり、運用者が利用者本人である場合の利点は [未決 9](#9-未決の事項) とする。
- 地域データは端末内のデータなので、取得済みの範囲の表示は外部への送信の設定に関係なく使える。
- オンライン地図に精度の上限（地区、地域）がある場合、上限より拡大した部分を地域データで描く組み合わせは、後の課題とする（[未決 12](#9-未決の事項)）。

### 6.15 ツール

今のツールでできること：

- `tools/basemap/build.sh` は、Protomaps の日次ビルドから go-pmtiles 1.31.2 の `extract`（`--region`、`--minzoom`、`--maxzoom`）で切り出す。ビルドの全体を取得せず、Range 要求で必要な部分だけを読む。
- `tools/basemap/assemble.py` は PMTiles v3 を読み、文字列の文字の範囲を集める。
- `tools/basemap/package.sh`、`release.sh` は archive、記述子、APK の固定値、公開のコマンドを作る。
- `tools/venues/build.sh`、`build_index.py` は Geofabrik の抽出から AVEN の索引を作る。

新たに要るもの：

| ツール | 内容 |
| --- | --- |
| `tools/regions/cells.py` | 範囲（`japan.geojson` など）と交わるズーム 8 の区画の一覧を作る |
| `tools/regions/build.sh` | 区画ごとに `pmtiles extract --bbox=<区画> --minzoom=8 --maxzoom=15` を実行する。区画の境界に接する隣のタイルが入らないよう、区画をわずかに内側に縮めた bbox を渡し、出力のタイルが区画の内側だけであることを確かめる（go-pmtiles の境界の扱いは未確認） |
| `tools/regions/measure.py` | 区画ごとの大きさとタイル数を出し、パックの大きさの分布を記録する。最初の作業とする |
| `tools/regions/package.sh`、`release.sh` | カタログ、APK の固定値（`regions-pin.json`）、リリースノート、アセットの分割した公開のコマンドを作る |
| `tools/basemap/` の変更 | パックの層の雛形を archive に加える。パックの文字列の文字の範囲もフォントに含める |
| `tools/venues/` の変更 | 区画の bbox で絞った索引を作る。日本の外は国ごとの Geofabrik の抽出から作る |

## 7. 脅威とプライバシーの分析

### 7.1 設定ごとに伝わるもの

| 設定 | 受け取る者 | 伝わるもの | そこから推測できること |
| --- | --- | --- | --- |
| オンライン地図、操作時のみ | 選んだ地図の配信元 | 同意した画面で表示した範囲（精度の粒度）、時刻、IP アドレス | 関心のある地域。現在地の近くを表示する習慣があれば現在地 |
| オンライン地図、自動 | 選んだ地図の配信元 | 加えて、フィード、期間、他の端末の静止画の範囲。過去の日の経路と滞在地を収める範囲 | 自宅、職場、移動の範囲、他の端末の所在 |
| オンライン地図、地域・地区 | 同上 | 範囲の粒度が約 10 km、約 1 km になる | 区画の単位の上記 |
| オンライン地図（カスタム） | 入力した URL のホスト | 上記と、URL の API キー | 上記が、配信元の利用者アカウントと結び付く |
| 地名検索、自動 | Geocoder の実装の提供者 | 索引で求まらない滞在地と、他の端末の現在地の座標（精度に従う）、問い合わせの時刻 | 滞在した場所、他の端末の所在。提供者の側で端末やアカウントと結び付くかは未確認 |
| 施設のオンライン検索、操作時のみ | 有効にした Overpass のインスタンス（最大 4） | 検索した位置（精度に従う）、時刻、IP アドレス、アプリの版 | その時刻にその場所付近にいたこと、または過去の訪問の場所 |
| データの取得、全域のみ | GitHub | 取得の時刻、IP アドレス、アプリの版 | アプリを使っていること |
| データの取得、区画 | GitHub | 加えて、選んだ区画（約 130 km 四方）の集合 | これから行く地域、または関心のある地域。過去でなく未来の行動を示しうる |
| 自動更新 | GitHub | 同じ区画の再取得と時刻 | 区画への関心が続いていること。IP アドレスを通じて期間をまたいで結び付く |
| 同期 | 同期サーバの運用者 | [`privacy.md`](../privacy.md) の表のとおり | 変わらない |

### 7.2 通信路の観察者

- 回線の事業者や Wi-Fi の運用者は、TLS の SNI と接続先の IP アドレスから、どの配信元に接続したかを知りうる（地理院タイルを使っている、Overpass に問い合わせた、など）。
- 地域データのパックは区画ごとに大きさが異なる。転送量から区画を推測されうる。詰め物（padding）で大きさを揃える対策は、容量の増加に見合わないので採らない。この残余は本書に記すにとどめる。

### 7.3 精度の限界

- 固定の格子に丸めても、格子の境界をまたぐ移動は伝わる。自動の送信を繰り返すと、区画の単位の移動の経路が伝わる。
- 地図の精度の上限は、表示範囲の粒度を粗くするだけである。表示範囲の広さ（数十 km）より細かい情報は送らないが、表示した場所そのものは伝わる。
- 表示の同意は、その画面で利用者が表示した範囲に限る。ただし、MapLibre は表示範囲の周囲や低いズームのタイルを先に読むことがあり、送る範囲は画面の範囲よりやや広い。
- 送信先を Never にしても、それ以前に送った情報は取り消せない。MapLibre の端末内のキャッシュは、送信を伴わないので消さない。

### 7.4 この設定で守らないもの

- OS の測位サービス（Google 位置情報の精度）が送る情報。
- 利用者が他のアプリに渡したもの（`geo:`、共有）。
- 同期サーバの運用者に見えるメタデータ（別の文書で扱う）。
- 地域データの配信元の運営者が、IP アドレスを他の情報と結び付けること。

## 8. 試験の計画

### 8.1 core の単体試験（JVM）

- `Policy` の符号化と復号：正準形だけを受け付ける。キーや送信先の重複、余分な項目、未知の版、選べない組を壊れたものとして扱い、既定の安全側に倒れる。
- 移行：`blockExternalLocation` が true、false、値なし、型違いの 4 通りと、`onlineVenues` の有無の組み合わせ。`mapConsents` の引き継ぎ。
- 同値性：旧設定の 2 通りから作った `Policy` について、新しい `BaseMapPolicy` と `GeocodePolicy` の判定が、今の関数と入力の全組み合わせ（地図の種類、同意、画面の表示、オフライン地図の有無）で一致する。
- `SendGate`：送信先ごとの世代。Geocoder の変更が地図の許可と静止画の票を無効にしないこと。地図の送信先の変更が、その送信先の許可と同意だけを消すこと。精度だけの変更でも消すこと。Never の送信先で `firstSuccess` が残りのインスタンスを試さないこと。
- `blockExternalLocation` の派生値：旧設定のオフと一致する場合だけ false。
- `Precision.snap`：格子の中心を返す。負の座標、180° 経線、極付近。同じ区画の点は同じ値になる。
- Overpass の問い合わせ：地区では区画の bbox だけを含み、元の座標を含まない（問い合わせ文字列に元の座標の桁が現れないことを確かめる）。
- `TileStyle.capped`：すべてのソースの `maxzoom` が上限以下になり、フォントとスプライトの URL を変えない。
- 地域データ：区画の計算（ズーム 8、境界、180° 経線）、枠と交わる区画、カタログの解析と検証、PMTiles のヘッダの範囲の検証、参照数による削除、`state.json` の書き込みの途中の中断、空きの不足（記録の領域を残す）、Range での再開と sha256 の不一致（今の偽の `RangeHttp` を使う）。
- 合成したスタイル：`OfflineBasemapStyle.remoteUrls` が空であること。

### 8.2 形式検証

- `formal/tla/SendGate.tla`（4.6 節）を CI のパスに加える。
- 変異として、世代を全体で一つに戻した版で「取り消しすぎない」性質が破れ、票の検査を外した版で「古い票で送らない」性質が破れることを確かめる。

### 8.3 端末での試験

- 通信の記録：デバッグ版で、`Outbound.open` と MapLibre の interceptor（使える場合）が出すすべての要求のホスト、パス、時刻を記録する。interceptor が使えない場合は、端末の外の HTTPS の中継で記録する。
- 次の筋書きごとに、記録が規則と一致することを確かめる。
  - 新規の導入：GitHub（オフライン地図、施設データ）以外へ送らない。
  - 旧設定 true と false からの更新：更新の前後で送信先と要求が変わらない。
  - 地図だけ自動：静止画とサムネイルが送り、Geocoder へは送らない。
  - Geocoder だけ地域：問い合わせの座標が 0.1° の格子の中心である。
  - 地図を地区：ズーム 16 以上でもズーム 15 を超える要求がない。
  - 規則の変更：待機中の静止画を捨て、実行中のものを中止し、変更の後に古い票で送らない。
  - Overpass の一部のインスタンスをオフ：そのホストへ送らない。
  - MapLibre 自体の通信：上記のどの筋書きでも、地図の配信元以外へ MapLibre が送らないこと。
- 地域データ：機内モードで、取得した区画の内側をズーム 15 まで描き、区画の外ではオフライン地図に戻る。境界の見た目、文字の重なり、パックの数を増やしたときの描画の時間。
- 記録との独立：記録モード「最高精度」で記録しながら大きなパックを取得し、記録の欠落がなく、空きが 256 MB を下回る前に取得が止まることを確かめる。
- 取得の中断：通信の切断、アプリの強制終了、端末の再起動の後に再開する。

### 8.4 画面の確認

- 「データの扱い」の ✓ ／ ⊖ の一覧を、色を除いた表示（グレースケール）で読めること。
- TalkBack で、各行の状態（送信する、送信しない）と時機が読み上げられること。
