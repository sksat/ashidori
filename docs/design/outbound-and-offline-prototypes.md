# 外部への送信の設定とオフラインの地域データ：試作の結果

> 状態：**試作の記録**。製品のコードは含まない。
> [`outbound-and-offline.md`](outbound-and-offline.md)（以下「設計」）の [8.3 節](outbound-and-offline.md#83-試作で確かめること) が求める二つの試作の方法と結果をまとめる。
> 計測の手順は `tools/proto/` に置く。MapLibre の試作のアプリのコードは枝 `spike/maplibre-intercept` にあり、main には入れない。
> 計測の日は 2026-11-18 である。

本書は二つの試作を扱う。

1. **区画ごとのパックの大きさ**：ズーム 8 の区画ごとに、ズーム 8〜15 のパックの大きさを実際に切り出して測る（設計 [6.4 節](outbound-and-offline.md#64-区画)、[未決 7、8](outbound-and-offline.md#9-未決の事項)）。
2. **MapLibre の要求の差し止め**：MapLibre Android 13.6.1 の HTTP クライアントに interceptor を挟み、印（トークン）がどの種類の最終の要求まで届くか、拒んだときの挙動、キャッシュ、出典の画面、テレメトリを確かめる（設計 [4.4 節](outbound-and-offline.md#44-outbound)）。

## 1. 区画ごとのパックの大きさ

### 1.1 方法

- 元データ：Protomaps の日次ビルド `https://build.protomaps.com/20261117.pmtiles`（139,547,428,331 バイト、PMTiles v3、ズーム 0〜15、tile type mvt、gzip）。メタデータは OSM の差分の時刻 2026-11-17T04:00:00Z、planetiler 0.10.2、basemap のスキーマの版 4.15.2 である。
- 道具：go-pmtiles 1.31.2（`tools/basemap/build.sh` が固定する版。配布物の sha256 `3ed7dbf4…a312f` を確かめた）。
- 遠隔のファイルに対して `pmtiles extract` を実行した。ビルドの全体は取得せず、ディレクトリとタイルを HTTP の Range 要求で読む。
- 区画は `tools/proto/cells.py` で求める。ズーム 8 のタイルの範囲を `--bbox` に渡し、`--minzoom=8 --maxzoom=15` とした。
- 日本の全区画（`tools/basemap/japan.geojson` と交わる 136 区画）は `--dry-run` で測った（`tools/proto/dryrun_cells.sh`）。dry-run はディレクトリだけを読み、出力の大きさを SI 単位の 3 桁に丸めて表示する。
- 代表の 9 区画は実際に切り出し（`tools/proto/extract_cells.sh`）、ファイルの大きさ、タイル数、区画の外のタイルの有無、ズームごとのバイト数を `tools/proto/pmtiles_list.py` で数えた。dry-run の値は実測と丸めの範囲で一致した（東京 327 MB に対し 326,729,002 バイト、大阪 219 MB に対し 218,740,653 バイト）。
- 日本全体は、今の `build.sh` と同じく `japan.geojson` を `--region` に渡し、ズーム 6 から各最大ズームまでを dry-run で測った（`tools/proto/dryrun_japan.sh`）。
- 文字の範囲は `tools/proto/glyph_ranges.py`（`assemble.py` の規則を流用）で、切り出したパックのラベルの文字列から求めた。

### 1.2 区画の境界の扱い

区画の範囲をそのまま `--bbox` に渡すと、隣の区画のタイルが入る。

| bbox | タイル数 | 区画の外のタイル | 大きさ（東京 `8-227-100`） |
| --- | --- | --- | --- |
| 区画の範囲そのまま | 22,363 | 518（各ズームで東の 1 列、南の 1 行、南東の 1 個） | 334,392,067 バイト |
| 各辺を 1e-7° 内側に縮める | 21,845 | 0 | 326,729,002 バイト |

- go-pmtiles 1.31.2 は、bbox の東端と南端がタイルの境界に一致すると、その境界の先のタイルも含める。数は各ズーム z で `(2^(z-8) + 1)^2` となり、合計は `21,845 + 2 × 255 + 8 = 22,363` である。西端と北端は含めない。
- 1e-7° 縮めると、ズーム 8〜15 の区画の内側のタイル 21,845 個だけになる（ズーム 15 のタイルの 1 辺は約 0.011° であり、1e-7° は十分小さい）。代表の 9 区画すべてで区画の外のタイルは 0 だった。
- 隣り合う区画のパックは、縮めた bbox ではタイルを共有しない。重複は、海などの同じ内容のタイルを各パックが 1 個ずつ持つ分だけであり、無視できる（パックの中では同じ内容のタイルを 1 個にまとめる。東京は 21,845 タイルに対し内容 21,183 個）。
- パックのヘッダの bounds は渡した bbox になる。縮めた場合は区画の内側に収まり、設計 [6.5 節](outbound-and-offline.md#65-パックスタイルの束カタログ) のヘッダの検証（範囲が区画の内側）がそのまま使える。縮めない場合も bounds は区画と一致するが、中身は区画の外にはみ出す。ヘッダの検証だけでははみ出しを見つけられない。
- ディレクトリとメタデータの分は 1 パックあたり 6〜49 kB だった。

### 1.6 今のツールとの比較

`tools/basemap/build.sh` は同じ方法（遠隔の日次ビルドに対する `pmtiles extract`）で、次を作る。

- 日本：`--region=japan.geojson --minzoom=6 --maxzoom=10`。今の配布物（`basemap-20261013`、ビルド 20261013）の `japan.pmtiles` は 45,446,923 バイトである。ビルド 20261117 の dry-run（46 MB）とほぼ一致する。
- 全世界：`--maxzoom=5`。`world.pmtiles` は 15,056,936 バイトである。
- フォント 5,282,619 バイト（Noto Sans の 3 書体 × 256 範囲。中身があるのは 30 範囲）、スプライト 52,154 バイト、スタイル 155,559 バイト。
- archive は 63,591,472 バイト（APK の `basemap-pin.json` の sha256 と一致することを確かめた）。

今のツールに区画の切り出しはない。`build.sh` は `--region` で日本の長方形の集まりを切り出すだけであり、区画の bbox、境界の縮め、区画の外のタイルの検査はない。設計 6.15 節の `tools/regions/` が新たに要る。

文字の範囲：

- 代表の 9 パックの文字列は、MapLibre が端末で描く範囲（漢字、かな、ハングル）を除いて 41 範囲を要する。今のオフライン地図のフォント（30 範囲）にない範囲が 25 ある。
- 25 範囲の多くは記号（U+2100〜、U+2500〜、U+1F100〜 の絵文字など）と、基本多言語面の外の漢字（U+20B00〜 などの CJK 拡張 B 以降）、異体字セレクタ（U+E0100〜）である。基本多言語面の外の漢字は MapLibre の端末での描画の対象外であり、Noto Sans の glyph にもない。スタイルの束を作るときに、どの範囲を持つかを決める必要がある。

## 2. MapLibre の要求の差し止め

### 2.1 方法

- 版：アプリが使う MapLibre Android 13.6.1（`gradle/libs.versions.toml`）。OkHttp は MapLibre 13.6.1 が依存する 4.12.0 である。
- 試作のアプリ：枝 `spike/maplibre-intercept`（コミット `a919610`）。デバッグ版だけに `SpikeMapActivity` を加えた。MapView を一つ置き、`HttpRequestUtil.setOkHttpClient` に interceptor 付きの `OkHttpClient` を渡す。
- interceptor は、要求ごとに最終の URL、資源の種類、印、条件付き要求の見出し（`If-None-Match`、`If-Modified-Since`）を logcat に書く。印 `ashidori-t=<トークン>`（クエリ）または `/ashidori-t/<トークン>/`（パスの先頭）を取り除いてから送る。`files/spike-reject` に書いたトークンの要求は、送らずに拒む（403 または 404 の応答を作る、または `IOException` を投げる）。
- スタイルの与え方（「印の置き方」）を 4 通り試した。

| 名前 | スタイルの与え方 |
| --- | --- |
| direct | OpenFreeMap のスタイルの URL に印を付け、MapLibre にそのまま渡す（今のアプリと同じく URL で渡す） |
| url | アプリがスタイルを取得し、`sprite`、`glyphs`、ソースの `url`（TileJSON）に印（クエリ）を付けて JSON で渡す |
| tiles | url に加え、アプリが TileJSON も取得し、ソースを `tiles` の形に展開して印を付ける（設計 4.7 節の `TileStyle.capped` の形） |
| path | tiles と同じで、印をパスの先頭に置く |

地理院タイルは、今のアプリと同じ形のラスタのスタイルを JSON で作り、`tiles` の URL に印（クエリ）を付けた。

- 端末：エミュレータ `emulator-5554`（1080 × 2400）。表示は東京駅付近（北緯 35.681°、東経 139.767°）のズーム 14 とした。
- 実行の前に MapLibre の端末内のキャッシュ（`files/mbgl-offline.db`）を消し、アプリを強制終了してから起動した。手順は `tools/proto/maplibre_spike.sh` と `tools/proto/maplibre_spike2.sh`、要求の集計は `tools/proto/results/maplibre-requests-20261118.txt` にある。

### 2.2 資源の種類ごとの結果

MapLibre が出した最終の要求に印が残ったかを示す。「―」はその形では MapLibre が要求しない（アプリが取得する、または展開済み）ことを示す。

| 種類 | 最終の要求の例（印を除く） | direct | url | tiles | path |
| --- | --- | --- | --- | --- | --- |
| スタイル | `tiles.openfreemap.org/styles/liberty` | 印あり（渡した URL そのもの） | ― | ― | ― |
| TileJSON | `tiles.openfreemap.org/planet` | **印なし** | 印あり | ― | ― |
| ベクタタイル | `tiles.openfreemap.org/planet/<版>/{z}/{x}/{y}.pbf` | **印なし** | **印なし** | 印あり | 印あり |
| ラスタタイル（地理院） | `cyberjapandata.gsi.go.jp/xyz/std/{z}/{x}/{y}.png` | ― | ― | 印あり | 試していない |
| スプライト JSON（@2x） | `tiles.openfreemap.org/sprites/ofm_f384/ofm@2x.json` | **印なし** | 印あり | 印あり | 印あり |
| スプライト PNG（@2x） | `tiles.openfreemap.org/sprites/ofm_f384/ofm@2x.png` | **印なし** | 印あり | 印あり | 印あり |
| フォント | `tiles.openfreemap.org/fonts/Noto%20Sans%20Regular/0-255.pbf` | **印なし** | 印あり | 印あり | 印あり |
| そのほか | なし | なし | なし | なし | なし |

- スプライトは、MapLibre が `@2x.json`、`@2x.png` を **クエリの前に** 差し込む（`…/ofm@2x.json?ashidori-t=T1`）。印は展開の後も残る。
- フォントは、`{fontstack}`（URL 符号化した書体名）と `{range}` を展開した後も、クエリとパスの印が残る。
- TileJSON の URL に付けた印は、TileJSON が返すタイルの URL に引き継がれない。タイルに印を付けるには、TileJSON をアプリが取得し、`tiles` に展開して印を付ける必要がある（tiles と path の形）。
- direct の形では、スタイルの URL の印はスタイルの要求にしか残らない。今のアプリのように OpenFreeMap のスタイルを URL で渡す限り、interceptor はタイル、スプライト、フォントの持ち手を区別できない。
- 1 倍のスプライト（`ofm.json`、`ofm.png`）は、このエミュレータの画素密度では要求されなかった。Pixel 8a も 2 倍以上なので同じと見込むが、1 倍の展開での印の位置は確かめていない。
- OpenFreeMap のスタイルの `ne2_shaded`（ラスタ、ズーム 6 まで）は、ズーム 14 の表示では要求されなかった。
- 全実行を通じて、要求の送り先は `tiles.openfreemap.org` と `cyberjapandata.gsi.go.jp` だけだった。
- 地理院タイル（`tileSize` 256）は、表示のズーム 14 でズーム 15 のタイルを要求した（ズーム 11 の 1 枚と、ズーム 15 の 10 枚）。

**結論**：アプリがスタイルを書き換える形（tiles、path）では、MapLibre が出すすべての種類の最終の要求に印が届く。クエリとパスのどちらでも届く。設計 4.4 節の「印を運べない経路」（`Outbound` で取得して `file://` で参照）が要る種類は **ない**。スタイルと TileJSON はアプリが `Outbound` で取得するので、もともと MapLibre の要求にならない。

### 2.3 古い印の要求を拒んだときの挙動

印を拒む設定にしてから地図を開いた（キャッシュは空）。

| 拒み方 | 観察の時間 | interceptor に届いた要求 | 同じ URL の再要求 | 地図 | 落ちたか |
| --- | --- | --- | --- | --- | --- |
| 403 の応答を作る | 60 秒 | 21（スプライト 2、タイル 19） | なし（各 1 回） | 描画の完了の通知なし。表示中のタイルの親（ズーム 13〜3）を 1 回ずつ要求し、それも拒まれた | 落ちない |
| 404 の応答を作る | 60 秒 | 9（スプライト 2、タイル 7） | なし | タイルがないものとして扱い、描画の完了の通知が出た。親のタイルは要求しなかった | 落ちない |
| `IOException` を投げる | 90 秒 | 24（スプライト 2、タイル 22） | なし | 403 と同じく親のタイルを要求した | 落ちない |

- 表示の途中で印を古くした場合（ズーム 14 で描き終えた後に拒む設定にし、地図を動かした）も、新たに要る 8 タイルを 1 回ずつ要求し、拒まれた後に再要求はなかった。アプリは落ちなかった。
- MapLibre の再試行は失敗の種類で決まる。`HttpRequestImpl$OkHttpCallback.getFailureType` は、`NoRouteToHostException`、`UnknownHostException`、`SocketException`、`ProtocolException`、`SSLException` を接続の失敗（再試行する）、`InterruptedIOException` を一時的な失敗、そのほかを恒久的な失敗とする。interceptor が投げた素の `IOException` は恒久的な失敗になり、再試行されなかった。**接続の失敗に当たる例外（`SocketException` など）を投げてはいけない**。
- 403 と `IOException` は、失敗したタイルの代わりに低いズームのタイルを要求させる。拒んだ要求は端末の外に出ないので送信の面の問題はないが、要求の数は増える。
- 404 は MapLibre の端末内のキャッシュに「内容なし」として保存される可能性がある。保存されると、同じ印が後で有効になっても空のタイルが出うる。これは確かめていない。

最初の実行では、`IOException` の試験の開始から約 1.5 秒後にエミュレータの `system_server` が再起動し、試作のアプリも終わった。同じ試験を別の回でやり直し（上の表の値）、90 秒の間アプリは動き続けた。`system_server` の再起動は、出典の画面から Chrome を開いた時にも 2 回起きた。後で測ったエミュレータの空きのメモリ（`MemFree`）は約 89 MB、負荷の平均は約 10 だった。アプリの例外が `system_server` を止めることはないので、試作が原因ではないと判断した。

### 2.4 キャッシュ

OpenFreeMap（tiles の形）：

| 回 | 条件 | MapLibre の要求 | 地図 |
| --- | --- | --- | --- |
| 1 | キャッシュを消し、印 T1 | 14（タイル 7、スプライト 2、フォント 5） | 描画の完了 |
| 2 | 強制終了の後、同じ印 T1 | **0** | 描画の完了 |
| 3 | 強制終了の後、別の印 T2 | 14（1 回目と同じ） | 描画の完了 |
| 4 | 強制終了の後、印 T1 をすべて拒む設定 | **0** | 描画の完了 |

地理院タイル：

| 回 | 条件 | MapLibre の要求 | 応答 |
| --- | --- | --- | --- |
| 1 | キャッシュを消し、印 T1 | 11 | 200 |
| 2 | 強制終了の後、同じ印 T1 | 11（すべて `If-None-Match` 付き） | すべて 304 |

- MapLibre の端末内のキャッシュは、印を含む URL を鍵にする。**印が同じなら再起動の後もキャッシュが効き**、印が変わればすべて取得し直す。
- OpenFreeMap のタイルは `Cache-Control: max-age=315360000`（約 10 年）を返すので、キャッシュの内容が新しい間は要求を出さない。印を拒む設定でもキャッシュから描けた（4 回目）。スタイルは `max-age=86400`、TileJSON は `max-age=3600` だが、tiles の形ではアプリが取得するので MapLibre のキャッシュとは関係しない。
- 地理院タイルは `Cache-Control` も `Expires` も返さない（`ETag` と `Last-Modified` だけ）。MapLibre は表示のたびに条件付き要求で確かめ直す。**キャッシュがあっても、タイルの番号（表示範囲）は毎回送られる**。転送量は 304 で減る。
- 地理院タイルの 2 回目で印を拒んだ場合に、キャッシュから描けるかは確かめていない。

### 2.5 出典の画面

MapLibre 13.6.1 の `AttributionDialogManager.showMapAttributionWebPage` を逆アセンブルして確かめた。

- 出典の URL が `https://www.mapbox.com/map-feedback` か `https://apps.mapbox.com/feedback` を含む場合だけ、`buildMapFeedbackMapUrl` が `/経度/緯度/ズーム/方位/傾き` のカメラの位置を URL に付ける（MapLibre の API キーがあれば `access_token` も付ける）。
- それ以外の URL は、そのままブラウザへの Intent で開く。

アプリの地図の出典の URL は次のとおりで、どれも上の 2 つを含まない。

| 地図 | 出典のリンク |
| --- | --- |
| OpenFreeMap（TileJSON の `attribution`） | `https://openfreemap.org`、`https://www.openmaptiles.org/`、`https://www.openstreetmap.org/copyright` |
| 地理院タイル（アプリが書く） | `https://maps.gsi.go.jp/development/ichiran.html` |
| オフライン地図（`basemap-20261013` の `style.json`） | `https://www.openstreetmap.org/copyright`、`https://protomaps.com/`、`https://www.naturalearthdata.com/` |
| カスタム | 利用者が入力した出典の文字列（アプリは HTML として MapLibre に渡す） |

端末では、OpenFreeMap の出典の画面に「OPENFREEMAP」「© OPENMAPTILES」「OPENSTREETMAP」の 3 行が出た。前の 2 行を押すと、`https://openfreemap.org` と `https://www.openmaptiles.org/` がそのまま開かれた（`startActivity` に渡った URI を記録した）。カメラの位置は付かなかった。OpenStreetMap の行と地理院タイルの出典は、Chrome を開いた時のエミュレータの再起動のため端末では押していない。ソースの分岐から、座標は付かないと判断する。

**結論**：今の地図では、出典の画面がカメラの位置を送ることはない。例外はカスタムの出典の文字列であり、利用者が Mapbox の feedback の URL を書けば座標が付く。

### 2.6 テレメトリと User-Agent

- MapLibre Android 13.6.1 の AAR（`android-sdk-opengl-13.6.1.aar`）には、テレメトリのクラスがない。クラスと `libmaplibre.so` に「telem」の文字列はない。Mapbox の SDK にあった出典の画面の「テレメトリの設定」の行もない（出典の画面の行はソースの出典だけである）。
- `libmaplibre.so` に埋め込まれた URL は `https://api.mapbox.com`、`https://api.maptiler.com`、`https://demotiles.maplibre.org` である。これらは `mapbox://`、`maptiler://` の URL を解決する `TileServerOptions` の既定値であり、アプリはこれらの形の URL を使わない。
- 全実行で、interceptor に届いた要求の送り先は地図の配信元の 2 ホストだけだった。テレメトリや events の要求はなかった。ただし、interceptor を通らない通信がないことは、端末の外の中継では確かめていない（設計 8.4 節の必須の試験として残る）。
- AAR の manifest は `INTERNET`、`ACCESS_NETWORK_STATE`、`ACCESS_WIFI_STATE`、`ACCESS_COARSE_LOCATION`、`ACCESS_FINE_LOCATION` を宣言する。
- User-Agent は `"%s %s (%s) Android/%s (%s)"` に、`<パッケージ名>/<versionName> (<versionCode>)`、`MapLibre Android/13.6.1`、`c7506d6`、SDK の版、対応する ABI を入れた文字列である。**アプリのパッケージ名と版が地図の配信元に伝わる**。interceptor で置き換えられる。
